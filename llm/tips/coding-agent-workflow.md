# 用 Agent 高效开发

## 一句话

人定方向，Agent 出草稿，人收口。实现可以下放；接口、数据兼容、安全边界不要全权下放。

## 推荐节奏

```text
Ask / Plan 读代码、列影响面、给方案
        ↓ 方案确认
Agent 按范围改代码、补测试
        ↓
人看 diff + 跑验收命令
        ↓
把有效约束沉淀进 AGENTS.md / rules / skills
```

探索和实现混在一次对话里，最容易改歪。跑偏了立刻停，不要在脏上下文上继续堆。

## 上下文怎么喂

- `@` 入口文件、类型定义、失败测试、对应设计文档
- 不要整仓倾倒；相关但未打开的文件，点名路径比「你自己找」稳
- 一个会话对应一个 PR 体量

## 人只做三件事

1. **定目标**：完成态、范围、硬约束
2. **看 diff**：接口是否变了、有没有顺手重构、有没有漏测
3. **跑验证**：测试、类型检查、最小复现

定位、改样板、补测试、按现有模式加功能，适合交给 Agent。

## 任务怎么分工

| 适合 Agent | 适合你先想清楚 |
|------------|----------------|
| 按现有模式补功能、修测试、改样板 | 架构、数据模型、跨服务协议 |
| 定位明确的 bug、补日志、写样例 | 产品取舍、安全/权限、迁移策略 |
| 把设计稿落成小 diff | 一次性大重构 |

## 复利点：沉淀 harness，而不是收藏 prompt

某次指令特别有效，就写成 rule / skill。当前 Agent 工程的主战场也在这里：规则、工具、session、eval，而不是更会「喊」模型。

Cursor 里常见落点：

- `AGENTS.md`：仓库级怎么协作
- `.cursor/rules`：语言/模块级约束
- skills：可复用的专项流程（review、修 CI、落设计稿）

## 没有验收命令就不要开工

改完立刻跑测试 / 类型检查 / 最小复现。prompt 里应写明命令，例如：

```text
验收：在 workspace-fe 下跑 pnpm typecheck；相关单测必须绿。
```
