# 03 评估与部署

## 1. 评估体系

Coding Agent SFT 需要 **多维度评估**，单一指标不够。

```
                    ┌─ 任务成功率（端到端）
                    │
SFT 模型评估 ───────┼─ 工具调用准确率（ToolBench）
                    │
                    ├─ 代码质量（lint pass rate）
                    │
                    └─ 通用能力（不退化检查）
```

### 1.1 端到端任务成功率

用固定 benchmark 任务集，跑完整 Agent 流程：

```python
tasks = [
    "创建一个 React 待办清单应用",
    "给现有项目添加用户登录功能",
    "修复 lint 报错并重构组件",
]

for task in tasks:
    result = agent.run(task, model=sft_model)
    score = evaluate(
        lint_passed=result.lint_ok,
        files_created=result.files,
        task_completed=result.finished,
    )
```

sh-mk 可用 `replay/repaly.py` 回放固定用例。

### 1.2 工具调用评估（ToolBench）

评估模型是否正确选择工具、生成合法参数：

| 指标 | 计算方式 |
|------|----------|
| Tool Selection Accuracy | 选对工具名 / 总数 |
| Argument Validity | JSON 可 parse 且字段完整 / 总数 |
| Execution Success | 工具执行成功 / 总数 |

数据格式参考 OpenAI function calling eval：

```json
{
  "messages": [...],
  "expected_tool": "str_replace_editor",
  "expected_args_keys": ["command", "path"]
}
```

### 1.3 代码质量

| 指标 | 方法 |
|------|------|
| Lint Pass Rate | `npm run lint` 通过率 |
| Build Success | `npm run build` 成功率 |
| Test Pass Rate | 单元测试通过率（如有） |

### 1.4 通用能力回归

确保 SFT 后基础能力不退化：

- HumanEval / MBPP（纯代码生成）
- 简单问答（不应只会写代码）
- 多轮对话连贯性

建议混合 10~20% 通用数据训练，或训练后做 regression test。

## 4. API 调用示例

### OpenAI 兼容 API + Tool Calling

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")

tools = [
    {
        "type": "function",
        "function": {
            "name": "str_replace_editor",
            "description": "Edit files in the workspace",
            "parameters": {
                "type": "object",
                "properties": {
                    "command": {"type": "string", "enum": ["view", "create", "replace"]},
                    "path": {"type": "string"},
                    "file_text": {"type": "string"},
                },
                "required": ["command", "path"],
            },
        },
    }
]

response = client.chat.completions.create(
    model="coding-sft-v1",
    messages=[
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": "创建一个待办清单应用"},
    ],
    tools=tools,
    tool_choice="auto",
    max_tokens=4096,
    temperature=0.7,
)

# 处理 tool_calls
if response.choices[0].message.tool_calls:
    for tc in response.choices[0].message.tool_calls:
        print(tc.function.name, tc.function.arguments)
```

## 5. A/B 测试

### 线上灰度

```
流量分配：
  90% → base model（稳定）
  10% → sft model（实验）

监控：
  - 任务完成率
  - 平均步数 / token 消耗
  - 用户满意度
  - 错误率
```

### 离线对比

用相同 prompt + 相同工具集，对比两个模型的完整 trajectory：

```bash
# 分别用 base 和 sft 跑同一 replay 模板
python sh-mk/replay/repaly.py --model base-32b --template replay.template.json
python sh-mk/replay/repaly.py --model sft-v1 --template replay.template.json
# 对比输出 diff
```

## 6. 迭代优化

```
SFT v1 → 评估 → 发现 tool selection 弱
    ↓
补充 tool calling 数据（针对性采集）
    ↓
SFT v2（混合 v1 数据 + 新数据）
    ↓
DPO / RLHF（可选，进一步优化偏好）
```

### DPO（可选进阶）

当 SFT 后需要进一步优化行为偏好：

```bash
# LLaMA-Factory DPO
llamafactory-cli train \
  --stage dpo \
  --model_name_or_path ./output/coding-sft-v1/merged \
  --dataset coding_agent_dpo \
  --pref_beta 0.1 \
  --finetuning_type lora
```

DPO 数据格式（chosen vs rejected trajectory）：

```json
{
  "conversations": [...],
  "chosen": {"from": "gpt", "value": "正确的工具调用和代码"},
  "rejected": {"from": "gpt", "value": "错误的工具选择或代码"}
}
```
