# 05 预训练基础

预训练（Pre-training）是 LLM 能力的根基：通过在海量无标注文本上学习语言建模目标，获得通用的语言理解、推理和知识记忆能力。

## 1. 预训练在整体链路中的位置

```
原始文本语料
    ↓  数据工程（清洗、去重、过滤、配比）
Tokenizer 编码
    ↓  CLM / MLM 目标
大规模分布式训练（Weeks~Months，数千 GPU）
    ↓
Base Model（基座模型）
    ↓  可选：Continued Pretrain（领域续训）
    ↓  后训练：SFT → DPO/RLHF
Instruct / Chat Model
```

| 阶段 | 数据 | 目标 | 典型规模 |
|------|------|------|----------|
| Pretrain | 无标注文本 | 下一 token 预测（CLM） | 1T~15T tokens |
| CPT | 领域文本 | 同上，继续 CLM | 10B~500B tokens |
| SFT | 指令/对话/轨迹 | 监督 CE loss | 1M~100M tokens |

## 2. 预训练目标

### 2.1 Causal Language Modeling（CLM）

当前 LLM 的主流目标。给定前文，预测下一个 token：

```
输入:  [BOS] 今天 天气 很 好
标签:       今天  天气  很  好 [EOS]
Loss:  -Σ log P(x_t | x_{<t})
```

实现要点：

```python
# 标准 next-token prediction
shift_logits = logits[..., :-1, :].contiguous()
shift_labels = labels[..., 1:].contiguous()
loss = F.cross_entropy(
    shift_logits.view(-1, vocab_size),
    shift_labels.view(-1),
    ignore_index=-100,  # padding 不参与 loss
)
```

### 2.2 其他目标（了解即可）

| 目标 | 代表 | 特点 |
|------|------|------|
| MLM | BERT | 双向，适合理解任务，生成能力弱 |
| UL2 / Mixture of Denoisers | PaLM 2, T5 | 多种 mask 模式混合 |
| Multi-token Prediction | Meta 2024 | 一次预测多个 future token，加速推理 |

**结论**：做生成式 LLM，CLM 是默认选择。

## 3. 数据工程

数据质量决定模型上限。工业级预训练数据 pipeline 通常包含以下阶段：

```mermaid
flowchart LR
    A[原始爬取] --> B[格式提取]
    B --> C[语言识别]
    C --> D[质量过滤]
    D --> E[去重]
    E --> F[PII 移除]
    F --> G[毒性/安全过滤]
    G --> H[配比混合]
    H --> I[Tokenize 缓存]
```

### 3.1 常见数据来源

| 类型 | 示例 | 占比（参考 LLaMA/Qwen） |
|------|------|------------------------|
| Web 爬取 | Common Crawl, C4 | 50~70% |
| 代码 | GitHub, StackOverflow | 5~15% |
| 书籍 | Books3, 电子书 | 2~5% |
| 百科/学术 | Wikipedia, arXiv | 2~10% |
| 对话/论坛 | Reddit, 贴吧 | 5~10% |
| 合成/翻译 | 回译、LLM 生成 | 视需求 |

### 3.2 质量过滤

常用启发式规则：

```python
def quality_score(doc):
    """简化版质量评分"""
    lines = doc.split("\n")
    avg_line_len = sum(len(l) for l in lines) / max(len(lines), 1)

    return (
        len(doc) > 200                          # 太短丢弃
        and avg_line_len < 1000                 # 单行过长可能是表格/乱码
        and doc.count("http") / len(doc) < 0.1  # 链接密度
        and sum(c.isalpha() for c in doc) / len(doc) > 0.5  # 字母占比
    )
```

进阶：用 fastText 语言分类器、KenLM perplexity 过滤低质量文本。

### 3.3 去重

| 级别 | 方法 | 目的 |
|------|------|------|
| 文档级 | MinHash / SimHash | 去除近似重复网页 |
| 段落级 | 精确 hash | 去除 copy-paste |
| 跨数据集 | datasketch | 防止 benchmark 泄漏 |

**Benchmark 污染**是常见坑：训练集包含 MMLU/HumanEval 原题会导致评估虚高。需做 n-gram 级别的 benchmark dedup。

### 3.4 数据配比（Data Mixture）

不同来源按权重混合，影响模型能力分布：

```
web:     60%
code:    16%
books:    4%
wiki:     4%
math:     4%
multilingual: 12%
```

配比是「配方」，通常需多轮 ablation。代码比例高 → 代码能力强但可能牺牲部分通用对话。

### 3.5 存储格式

生产环境常用 **Megatron Indexed Dataset** 或 **WebDataset (tar shards)**：

```
data/
├── shard_00000.tar   # 每个 tar 含多个 pre-tokenized 样本
├── shard_00001.tar
└── index.json        # 样本偏移索引
```

Pre-tokenize 到磁盘可大幅加速训练时的 DataLoader。

## 4. Tokenizer

### 4.1 主流算法

| 算法 | 代表 | 特点 |
|------|------|------|
| BPE | GPT-2, LLaMA | 合并高频 byte pair |
| SentencePiece BPE | LLaMA 2/3, Qwen | 不依赖空格分词，多语言友好 |
| Unigram | T5 | 从大词表 pruning |

### 4.2 词表大小权衡

| 词表大小 | 优势 | 劣势 |
|----------|------|------|
| 32K | Embedding 小 | 中文/代码压缩率低 |
| 100K~150K | 多语言/代码友好 | Embedding 参数增多 |
| 256K+ | 极高压缩率 | 训练更难收敛，小语种可能 under-represented |

中文场景：100K+ 词表可显著降低 token 数（同样文本 token 少 → 上下文能塞更多内容）。

### 4.3 训练 Tokenizer

```bash
# 使用 SentencePiece 训练 BPE
spm_train \
  --input=corpus.txt \
  --model_prefix=tokenizer \
  --vocab_size=151936 \
  --model_type=bpe \
  --byte_fallback=true \
  --split_by_unicode_script=true
```

## 5. 模型架构要点

现代 LLM 架构（LLaMA / Qwen / Mistral 系）的共同选择：

| 组件 | 选择 | 说明 |
|------|------|------|
| 归一化 | Pre-RMSNorm | 比 LayerNorm 快，训练更稳定 |
| 激活 | SwiGLU | 比 GELU 表达力更强 |
| 位置编码 | RoPE | 支持外推，长上下文扩展基础 |
| Attention | GQA / MQA | 减少 KV Cache，加速推理 |
| 词表 | 大 BPE | 见上 |

### 5.1 长上下文扩展

预训练通常 4K~8K context，后续通过以下方式扩展：

| 方法 | 原理 |
|------|------|
| RoPE Scaling (NTK, YaRN) | 调整频率基，推理时外推 |
| Long Context CPT | 长文档继续预训练 |
| Position Interpolation | 线性插值位置 |

## 6. Scaling Laws（缩放定律）

### 6.1 Chinchilla 最优

DeepMind Chinchilla 论文核心结论：**给定算力预算，模型参数量和训练 token 数应等比缩放**。

```
最优 token 数 ≈ 20 × 参数量（单位：tokens per parameter）

例：7B 模型  → ~140B tokens
    70B 模型 → ~1.4T tokens
```

很多早期模型（如原始 LLaMA-65B）是 **under-trained**（token 不够）；Chinchilla-70B 用更少参数但更多 token，效果反超。

### 6.2 三个缩放维度

```
Loss ∝ N^(-α)   # 模型参数量 N
Loss ∝ D^(-β)   # 训练 token 数 D
Loss ∝ C^(-γ)   # 总算力 C
```

实际决策：在固定 GPU 预算下，选「更小模型 + 更多 token」还是「更大模型 + 更少 token」，Chinchilla 给了理论指导。

### 6.3 Compute-Optimal 估算

```python
def chinchilla_tokens(params_b):
    """params_b: 参数量（十亿）"""
    return params_b * 20e9  # 返回 token 数

# 7B → 140B tokens
# 若训练 1T tokens → 适合 ~50B 参数模型
```

## 7. 训练超参数（Pretrain）

| 参数 | 7B 参考 | 70B 参考 | 说明 |
|------|---------|----------|------|
| Global Batch Size | 4M tokens | 4M~8M tokens | 以 token 数计，非 sample 数 |
| Learning Rate | 3e-4 | 1.5e-4 | 随模型规模减小 |
| LR Schedule | Cosine decay | Cosine decay | 衰减到 min_lr = 0.1 × peak_lr |
| Warmup | 2000 steps | 2000 steps | 通常按 step 而非 ratio |
| Weight Decay | 0.1 | 0.1 | |
| Precision | BF16 | BF16 | FP8 在 Hopper+ 上可用 |
| Sequence Length | 4096 | 4096~8192 | CPT 可加长 |

### Loss 曲线预期

```
Step 0~1K:    Loss 快速下降（warmup 期）
Step 1K~100K: 稳定下降
Step 100K+:   缓慢下降，接近收敛
```

若 loss 震荡或不降：检查数据（是否有空样本）、LR（是否过大）、梯度裁剪（max_grad_norm=1.0）。

## 8. Continued Pretrain（CPT / 领域续训）

在已有基座上继续 CLM，注入领域知识。比从零 Pretrain 成本低得多。

### 8.1 适用场景

- 代码 Agent：在代码语料上 CPT → 再 SFT
- 医疗/法律：领域文档 CPT
- 企业内部：私有文档 CPT

### 8.2 CPT vs SFT

| | CPT | SFT |
|---|-----|-----|
| 数据 | 无标注纯文本 | 指令/对话/轨迹 |
| 格式 | 连续文本 | 结构化 messages |
| LR | 1e-5 ~ 3e-5（低于 pretrain） | 1e-5 ~ 2e-5 |
| Token 量 | 通常 10B~100B+ | 通常 1M~100M |
| Loss mask | 全部 token | 通常只 mask assistant |

### 8.3 CPT 命令示例（LLaMA-Factory）

```yaml
stage: pt                    # pretrain stage
model_name_or_path: Qwen/Qwen2.5-7B
dataset: code_corpus
finetuning_type: full
learning_rate: 2.0e-5
num_train_epochs: 1
cutoff_len: 8192
```

```bash
llamafactory-cli train examples/train_full/code_cpt.yaml
```

## 10. 从零 Pretrain 的最小实践

适合学习，不适合生产：

```bash
# 1. 准备纯文本语料
cat wiki.txt code.txt > corpus.txt

# 2. 转 LLaMA-Factory 预训练格式（每行一段文本）
python -c "
for line in open('corpus.txt'):
    print(json.dumps({'text': line.strip()}))
" > pt_data.jsonl

# 3. 注册 dataset 并启动
llamafactory-cli train \
  --stage pt \
  --model_name_or_path gpt2 \
  --dataset pt_corpus \
  --finetuning_type full \
  --learning_rate 5e-4 \
  --num_train_epochs 3 \
  --per_device_train_batch_size 4 \
  --cutoff_len 1024
```

观察 **perplexity**（= exp(loss)）是否持续下降。

## 11. 检查清单

- [ ] 语料已去重，无 benchmark 污染
- [ ] Tokenizer 与目标模型匹配（或重新训练）
- [ ] Global batch size 以 token 数计算合理
- [ ] LR schedule 含 warmup + cosine decay
- [ ] 多卡训练使用正确的并行策略（见 [07-分布式训练与优化.md](./07-分布式训练与优化.md)）
- [ ] 定期 save checkpoint + 监控 loss/perplexity
- [ ] CPT 学习率低于原始 pretrain
