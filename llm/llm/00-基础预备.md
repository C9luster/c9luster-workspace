## 1. Transformer 架构

现代 LLM（LLaMA / Qwen / Mistral）都基于 Transformer Decoder。理解下面 4 个组件，就能读懂 90% 的模型代码。

### 1.1 整体结构

```
Input Tokens
    ↓ Embedding + RoPE
    ↓
┌─ Decoder Layer × N ─────────────────────┐
│  RMSNorm → Self-Attention → 残差连接      │
│  RMSNorm → FFN (SwiGLU)    → 残差连接      │
└─────────────────────────────────────────┘
    ↓ RMSNorm
    ↓ Linear (lm_head)
Output Logits → 预测下一个 token
```

与原始 Transformer 的区别：

| 组件 | 原始 Transformer | 现代 LLM |
|------|-----------------|----------|
| 归一化 | Post-LayerNorm | **Pre-RMSNorm** |
| 激活函数 | ReLU / GELU | **SwiGLU** |
| 位置编码 | 绝对位置 Sinusoidal | **RoPE** |
| Attention | MHA | **GQA**（推理优化） |

### 1.2 Self-Attention

**核心思想**：每个 token 根据与其他 token 的相关性，加权聚合信息。

#### 计算步骤

**输入形状 `X: [batch, seq_len, hidden_dim]`**

| 维度 | 含义 | 直觉 |
|------|------|------|
| **batch** | 一次喂给模型多少条样本 | 并行处理几条句子/对话 |
| **seq_len** | 每条样本有多少个 token | 句子长度（含 padding） |
| **hidden_dim** | 每个 token 用多少维向量表示 | 模型的「宽度」，如 4096 |

可以把它想成一个三维表格：`batch` 是第几本书，`seq_len` 是书里第几个字，`hidden_dim` 是每个字的语义坐标（用几千个数字描述一个词）。

**例子**：Qwen2.5-7B（`hidden_dim=3584`），batch=2，每条 5 个 token：

```
X.shape = [2, 5, 3584]
           │  │   └── 每个 token 是 3584 维向量
           │  └────── 每条序列 5 个 token
           └───────── 2 条样本并行
```

这些数从哪来：

```
原始文本 "你好世界"
  → Tokenizer:  [151644, 8948, 198, ...]     seq_len = token 个数
  → Embedding:  每个 ID 映射为 hidden_dim 维向量
  → 加 RoPE 位置编码
  → X: [batch, seq_len, hidden_dim]
```

| 配置项 | 对应维度 |
|--------|----------|
| `per_device_train_batch_size` | batch |
| `cutoff_len` / `max_length` | seq_len 上限 |
| 模型 `config.json` 的 `hidden_size` | hidden_dim |

显存大致与 `batch × seq_len × hidden_dim` 成正比，长上下文或加大 batch 都容易 OOM。

```
输入 X: [batch, seq_len, hidden_dim]

1. 线性投影得到 Q, K, V
   Q = X @ W_q    # [batch, seq, hidden]
   K = X @ W_k
   V = X @ W_v

2. 拆成多头（Multi-Head）
   Q = reshape → [batch, num_heads, seq, head_dim]
   K, V 同理

3. 计算注意力分数
   scores = Q @ K^T / sqrt(head_dim)    # [batch, heads, seq, seq]

4. Causal Mask（Decoder 专用，只能看左边）
   scores[i][j] = -inf  if j > i

5. Softmax + 加权求和
   attn = softmax(scores, dim=-1)
   output = attn @ V                      # [batch, heads, seq, head_dim]

6. 合并多头 + 输出投影
   output = concat(heads) @ W_o           # [batch, seq, hidden]
```

#### 代码实现（单层简化版）

```python
import torch
import torch.nn.functional as F
import math

def self_attention(x, W_q, W_k, W_v, W_o, num_heads, head_dim):
  """
  x: [batch, seq_len, hidden_dim]
  """
  batch, seq_len, hidden_dim = x.shape

  # 1. 投影
  Q = x @ W_q   # [batch, seq, hidden]
  K = x @ W_k
  V = x @ W_v

  # 2. 拆多头: [batch, seq, heads, head_dim] → [batch, heads, seq, head_dim]
  Q = Q.view(batch, seq_len, num_heads, head_dim).transpose(1, 2)
  K = K.view(batch, seq_len, num_heads, head_dim).transpose(1, 2)
  V = V.view(batch, seq_len, num_heads, head_dim).transpose(1, 2)

  # 3. Attention scores
  scores = Q @ K.transpose(-2, -1) / math.sqrt(head_dim)

  # 4. Causal mask: 下三角可见
  mask = torch.triu(torch.ones(seq_len, seq_len), diagonal=1).bool()
  scores = scores.masked_fill(mask, float('-inf'))

  # 5. Softmax + 加权
  attn = F.softmax(scores, dim=-1)
  out = attn @ V   # [batch, heads, seq, head_dim]

  # 6. 合并多头
  out = out.transpose(1, 2).contiguous().view(batch, seq_len, hidden_dim)
  return out @ W_o
```

#### 关键直觉

- **Q（Query）**：「我在找什么信息？」
- **K（Key）**：「我能提供什么信息？」
- **V（Value）**：「我的实际内容是什么？」
- **Causal Mask**：保证自回归——预测第 t 个 token 时，只能看到 0~t-1

#### GQA（Grouped Query Attention）

推理瓶颈在 KV Cache 显存。GQA 让多个 Q head 共享同一组 K/V head：

```
MHA:  num_q_heads = num_kv_heads = 32     # 每 head 独立 KV
GQA:  num_q_heads = 32, num_kv_heads = 8  # 4 个 Q head 共享 1 组 KV
MQA:  num_q_heads = 32, num_kv_heads = 1   # 所有 Q 共享 1 组 KV（极端）
```

LLaMA 3 / Qwen2.5 均使用 GQA，在质量与推理效率间取平衡。

### 1.3 RoPE（Rotary Position Embedding）

**问题**：Attention 本身不含位置信息，需要告诉模型 token 的顺序。

**RoPE 思路**：用旋转矩阵把位置信息编码进 Q 和 K，使注意力分数自然依赖相对位置。

```
对第 m 个位置的 Q/K 向量，按维度两两分组旋转 θ·m 角度：

┌ q_0 ┐     ┌ cos(mθ₁)  -sin(mθ₁) ┐   ┌ q_0 ┐
│ q_1 │  =  │ sin(mθ₁)   cos(mθ₁) │ × │ q_1 │
└  ·  ┘     └       ·          ·   ┘   └  ·  ┘

θᵢ = 10000^(-2i/d)    # 不同维度组用不同频率
```

**关键性质**：
- 相对位置编码：`<q_m, k_n>` 只依赖 `m - n`
- 支持外推：训练 4K context，推理时可扩展到 32K+（配合 NTK/YaRN scaling）

```python
def precompute_rope(dim, max_seq_len, theta=10000.0):
  """预计算 cos/sin 表，推理时查表"""
  freqs = 1.0 / (theta ** (torch.arange(0, dim, 2).float() / dim))
  positions = torch.arange(max_seq_len)
  angles = torch.outer(positions, freqs)  # [seq, dim/2]
  return torch.cos(angles), torch.sin(angles)

def apply_rope(x, cos, sin, position):
  """x: [batch, heads, seq, head_dim]"""
  x1, x2 = x[..., ::2], x[..., 1::2]
  rotated = torch.cat([
    x1 * cos[position] - x2 * sin[position],
    x1 * sin[position] + x2 * cos[position],
  ], dim=-1)
  return rotated
```

### 1.4 RMSNorm

LayerNorm 的简化版，去掉均值中心化，只做缩放：

```
RMSNorm(x) = x / RMS(x) × γ

RMS(x) = sqrt(mean(x²) + ε)
γ: 可学习的缩放参数
```

```python
class RMSNorm(torch.nn.Module):
  def __init__(self, dim, eps=1e-6):
    super().__init__()
    self.weight = torch.nn.Parameter(torch.ones(dim))
    self.eps = eps

  def forward(self, x):
    rms = torch.sqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
    return x / rms * self.weight
```

**为什么用 Pre-Norm**：归一化放在子层（Attention / FFN）**之前**，梯度传播更稳定，深层模型更好训。

```
Pre-Norm（现代 LLM）:  x → Norm → Attention → +x → Norm → FFN → +x
Post-Norm（原始）:     x → Attention → Norm → +x → FFN → Norm → +x
```

### 1.5 SwiGLU（FFN 激活）

FFN（Feed-Forward Network）是 Attention 之外的另一核心子层：

```
标准 FFN:  FFN(x) = W₂ · GELU(W₁ · x)
SwiGLU:    FFN(x) = W₂ · (Swish(W₁ · x) ⊙ W₃ · x)
                         ↑ gate 门控
```

- `Swish(x) = x · sigmoid(x)`
- `⊙` 是逐元素乘法（gate 控制信息流）
- 参数量约为标准 FFN 的 2/3（因 hidden_dim 调整），但表达力更强

```python
class SwiGLUFFN(torch.nn.Module):
  def __init__(self, dim, hidden_dim):
    super().__init__()
    self.w1 = torch.nn.Linear(dim, hidden_dim, bias=False)  # gate
    self.w2 = torch.nn.Linear(hidden_dim, dim, bias=False)  # down
    self.w3 = torch.nn.Linear(dim, hidden_dim, bias=False)  # up

  def forward(self, x):
    return self.w2(F.silu(self.w1(x)) * self.w3(x))
    # F.silu = Swish
```

### 1.6 完整 Decoder Layer 伪代码

```python
class DecoderLayer(torch.nn.Module):
  def forward(self, x, cos, sin):
    # Pre-Norm Attention
    h = x + self.attention(self.rms_norm1(x), cos, sin)
    # Pre-Norm FFN
    out = h + self.ffn(self.rms_norm2(h))
    return out
```

## 2. PyTorch 分布式

单卡放不下或训太慢时，需要多卡并行。最基础、最常用的方案是 **DDP（数据并行）**。

### 2.1 核心概念

| 概念 | 说明 |
|------|------|
| **进程（Process）** | 每张 GPU 对应一个独立进程 |
| **进程组（Process Group）** | 一组需要通信的进程 |
| **Rank** | 进程在组内的编号（0, 1, 2, ...） |
| **World Size** | 进程组总进程数 |
| **Local Rank** | 当前节点内的 GPU 编号 |
| **AllReduce** | 所有进程的数据做归约（如求和），结果广播回每个进程 |

### 2.2 通信原语

```
AllReduce:  所有进程的 tensor 求和/平均，每个进程拿到相同结果
            GPU0: [1,2]  ─┐
            GPU1: [3,4]  ─┤→  AllReduce(SUM)  →  每个 GPU: [4,6]

AllGather:  收集所有进程的 tensor 拼接
            GPU0: [a]  ─┐
            GPU1: [b]  ─┤→  AllGather  →  每个 GPU: [a, b]

Broadcast:  从 rank 0 广播到所有进程

ReduceScatter: AllReduce + 分片，每进程只保留一部分
```

### 2.3 DDP 工作流程

```
每个 GPU:
  1. 持有完整模型副本
  2. 处理不同的 data batch
  3. forward → 计算本地 loss
  4. backward → 计算本地梯度
  5. AllReduce 所有 GPU 的梯度（求平均）
  6. 用同步后的梯度更新参数（所有副本保持一致）
```

```
         ┌─── GPU0: batch_0 → grad_0 ──┐
         │                            │ AllReduce
Init ────├─── GPU1: batch_1 → grad_1 ──┤ (平均梯度)
         │                            │
         └─── GPU2: batch_2 → grad_2 ──┘
                    ↓
              所有 GPU 同步更新
```

### 2.4 最小 DDP 示例

```python
import os
import torch
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP
from torch.utils.data.distributed import DistributedSampler

def setup():
  """初始化进程组"""
  dist.init_process_group(backend="nccl")  # GPU 通信用 NCCL
  local_rank = int(os.environ["LOCAL_RANK"])
  torch.cuda.set_device(local_rank)
  return local_rank

def cleanup():
  dist.destroy_process_group()

def train():
  local_rank = setup()
  device = torch.device(f"cuda:{local_rank}")

  model = MyModel().to(device)
  model = DDP(model, device_ids=[local_rank])

  dataset = MyDataset()
  # 关键：DistributedSampler 确保每张卡拿到不同数据
  sampler = DistributedSampler(dataset, shuffle=True)
  loader = torch.utils.data.DataLoader(dataset, sampler=sampler, batch_size=4)

  optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)

  for epoch in range(num_epochs):
    sampler.set_epoch(epoch)  # 保证每 epoch shuffle 不同
    for batch in loader:
      batch = batch.to(device)
      loss = model(batch).loss
      loss.backward()
      optimizer.step()
      optimizer.zero_grad()
      # DDP 自动在 backward 时 AllReduce 梯度

  cleanup()

# 启动命令（4 卡）:
# torchrun --nproc_per_node=4 train.py
```

### 2.6 有效 Batch Size

```
Effective Batch Size = per_device_batch × num_gpus × gradient_accumulation_steps

例: 4 卡, per_device=2, accum=4
  → Effective = 2 × 4 × 4 = 32
```

梯度累积（显存不够大 batch 时）：

```python
accumulation_steps = 4
for i, batch in enumerate(loader):
  loss = model(batch).loss / accumulation_steps
  loss.backward()
  if (i + 1) % accumulation_steps == 0:
    optimizer.step()
    optimizer.zero_grad()
```

### 2.7 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 多卡 loss 不一致 | 未用 DistributedSampler | 检查 sampler |
| Hang 住 | NCCL 超时 / 端口冲突 | 换 `master_port`，查网络 |
| 速度没提升 | batch 太小，通信占比高 | 增大 per_device batch |
| OOM | 每卡仍存完整模型 | 换 ZeRO（见 [07-分布式训练与优化.md](./07-分布式训练与优化.md)） |

## 4. 训练基础概念

### 4.1 Loss 函数

#### Cross-Entropy Loss（CLM / SFT 核心）

语言模型的标准 loss：预测下一个 token 的交叉熵。

```python
import torch.nn.functional as F

# logits: [batch, seq_len, vocab_size]  模型输出
# labels: [batch, seq_len]              真实 token ID

# 关键：shift 一位，用前 n-1 个 token 预测后 n-1 个 token
shift_logits = logits[..., :-1, :].contiguous()
shift_labels = labels[..., 1:].contiguous()

loss = F.cross_entropy(
  shift_logits.view(-1, vocab_size),
  shift_labels.view(-1),
  ignore_index=-100,   # padding 和 mask 的位置不参与 loss
)
```

**直觉**：

```
输入:  [BOS] 今天 天气 很 好
预测:   今天  天气  很  好 [EOS]
         ↑     ↑    ↑   ↑
       每个位置预测下一个 token，算 CE loss
```

**SFT 与 Pretrain 的 loss 区别**：

| | Pretrain | SFT |
|---|----------|-----|
| 计算范围 | 所有 token | 通常只算 assistant token |
| labels | = input_ids（shift 后） | user/system 部分设为 -100 |
| 目标 | 学语言分布 | 学指令遵循 |

```python
# SFT loss mask 示例
labels = input_ids.clone()
labels[:user_token_end] = -100   # user 部分不计算 loss
labels[padding_positions] = -100  # padding 不计算 loss
# 只有 assistant 部分的 labels 保留原值
```

#### Perplexity（困惑度）

```
Perplexity = exp(loss)

loss=2.0 → PPL=7.4    （平均在 7.4 个 token 间犹豫）
loss=1.0 → PPL=2.7
loss=0.5 → PPL=1.6    （很好）
```

训练时看 loss 下降；评估时用 perplexity 更直观。

### 4.2 Learning Rate Schedule

固定 LR 训练不稳定。标准做法：**Warmup + Decay**。

```
LR
 ↑
 │    ╱‾‾‾‾╲
 │   ╱       ╲
 │  ╱  warmup  ╲___ cosine decay
 │ ╱                 ╲___
 └────────────────────────→ steps
   0   warmup_steps    total_steps
```

#### Warmup（预热）

训练初期梯度方向不稳定，从小 LR 线性增加到目标 LR：

```python
# 前 warmup_steps 步，LR 从 0 线性增加到 peak_lr
# step 0:     lr = 0
# step 500:   lr = peak_lr × (500 / warmup_steps)
# step 1000:  lr = peak_lr  (warmup 结束)
```

```yaml
# LLaMA-Factory / HF Trainer
warmup_ratio: 0.1        # 前 10% steps 用于 warmup
# 或
warmup_steps: 100        # 固定步数
```

**为什么需要**：初始随机权重产生的梯度可能很大，直接用大 LR 会导致 loss 爆炸。

#### Cosine Decay（余弦退火）

Warmup 后，LR 按余弦曲线平滑衰减到接近 0：

```python
import math

def cosine_lr(step, total_steps, warmup_steps, peak_lr, min_lr=0):
  if step < warmup_steps:
    return peak_lr * step / warmup_steps
  progress = (step - warmup_steps) / (total_steps - warmup_steps)
  return min_lr + 0.5 * (peak_lr - min_lr) * (1 + math.cos(math.pi * progress))
```

```yaml
lr_scheduler_type: cosine
learning_rate: 2e-5
```

#### 常见 Schedule 对比

| 类型 | 特点 | 适用 |
|------|------|------|
| `constant` | 不变 | 仅调试 |
| `linear` | 线性衰减到 0 | 简单场景 |
| `cosine` | 平滑衰减 | **最常用** |
| `cosine_with_restarts` | 周期性重启 | 探索性训练 |

### 4.3 Gradient Clipping（梯度裁剪）

防止梯度爆炸（尤其 RNN/大模型训练初期）：

```python
# 在 optimizer.step() 之前
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()
```

**原理**：计算所有参数梯度的 L2 范数，若超过 `max_norm` 则等比缩放：

```
total_norm = sqrt(Σ grad²)
if total_norm > max_norm:
  grad = grad × (max_norm / total_norm)
```

```yaml
# HF Trainer 默认开启
max_grad_norm: 1.0
```

**何时关注**：
- `grad_norm > 100`：LR 可能太大，或数据有问题
- `grad_norm < 0.01`：可能梯度消失，检查模型结构

### 4.4 其他关键训练技巧

#### Weight Decay

L2 正则化，防止过拟合：

```python
optimizer = torch.optim.AdamW(model.parameters(), lr=2e-5, weight_decay=0.01)
```

AdamW 将 weight decay 与梯度更新解耦，比 Adam + L2 更正确。

#### Gradient Accumulation

显存不够大 batch 时，多步累积梯度再更新：

```
Step 1: forward(batch_1) → backward → grad 累积
Step 2: forward(batch_2) → backward → grad 累积
Step 3: forward(batch_3) → backward → grad 累积
Step 4: forward(batch_4) → backward → grad 累积
        optimizer.step()  ← 用 4 步累积的梯度更新
        optimizer.zero_grad()
```

等效 batch size 扩大 4 倍，显存只增加约 1 倍。

#### Mixed Precision（混合精度）

```python
# BF16 训练（A100/H100，推荐）
model = model.to(torch.bfloat16)
# 或用 HF Trainer: bf16=True

# FP16 + Loss Scaling（V100 等老卡）
scaler = torch.cuda.amp.GradScaler()
with torch.cuda.amp.autocast():
  loss = model(batch).loss
scaler.scale(loss).backward()
scaler.step(optimizer)
scaler.update()
```

BF16 与 FP32 共享指数范围，不需要 loss scaling，训练更稳定。

### 4.5 训练循环全景

```python
model.train()
optimizer = torch.optim.AdamW(model.parameters(), lr=peak_lr, weight_decay=0.01)
total_steps = len(loader) * num_epochs
warmup_steps = int(total_steps * 0.1)

for epoch in range(num_epochs):
  for step, batch in enumerate(loader):
    global_step = epoch * len(loader) + step

    # 1. 调整 LR
    lr = cosine_lr(global_step, total_steps, warmup_steps, peak_lr)
    for param_group in optimizer.param_groups:
      param_group["lr"] = lr

    # 2. Forward
    outputs = model(**batch)
    loss = outputs.loss / accumulation_steps

    # 3. Backward
    loss.backward()

    # 4. 每 accumulation_steps 步更新一次
    if (step + 1) % accumulation_steps == 0:
      torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
      optimizer.step()
      optimizer.zero_grad()

    # 5. 日志
    if global_step % log_interval == 0:
      print(f"step={global_step}, loss={loss.item():.4f}, lr={lr:.2e}")
```
