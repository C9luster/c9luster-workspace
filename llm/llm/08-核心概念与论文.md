## 1. 术语表

| 术语 | 英文 | 解释 |
|------|------|------|
| 预训练 | Pre-training | 无标注文本上 CLM 训练，获得基座能力 |
| 续训 | CPT / Continued Pretrain | 在基座上继续 CLM，注入领域知识 |
| 微调 | SFT / Fine-tuning | 有标注数据监督训练，学指令遵循 |
| 对齐 | Alignment | 让模型输出符合人类偏好/安全要求 |
| 偏好对 | Preference Pair | (prompt, chosen, rejected) 三元组 |
| 基座模型 | Base Model | Pretrain 产物，不会对话 |
| 指令模型 | Instruct Model | SFT 后，能遵循指令 |
| 词表 | Vocabulary | Token ↔ ID 映射表 |
| 分词 | Tokenization | 文本 → token ID 序列 |
| 上下文长度 | Context Length | 模型一次能处理的最大 token 数 |
| 有效 batch | Effective Batch Size | micro_batch × GPUs × grad_accum |
| 混合精度 | Mixed Precision | FP16/BF16 训练，FP32 累加 |
| 梯度累积 | Gradient Accumulation | 多步累积梯度再更新，模拟大 batch |
| 梯度裁剪 | Gradient Clipping | 限制 grad norm 防爆炸 |
| 学习率预热 | Warmup | 训练初期 LR 线性增加 |
| 余弦退火 | Cosine Decay | LR 按余弦曲线衰减 |
| 困惑度 | Perplexity | exp(loss)，越低越好 |
| 缩放定律 | Scaling Laws | 模型性能与参数/token/算力的幂律关系 |
| 灾难性遗忘 | Catastrophic Forgetting | 微调后丢失预训练能力 |
| 模式崩溃 | Mode Collapse | RL 训练中输出多样性丧失 |
| KL 散度 | KL Divergence | 衡量两个分布差异，RL 中约束策略偏移 |
| LoRA | Low-Rank Adaptation | 低秩矩阵近似，高效微调 |
| MoE | Mixture of Experts | 稀疏激活，增大参数但不增计算 |
| GQA | Grouped Query Attention | 多 Q head 共享 KV head，省 KV Cache |
| RoPE | Rotary Position Embedding | 旋转位置编码 |
| MFU | Model FLOPs Utilization | 实际算力 / 峰值算力 |

## 2. 核心公式

### 2.1 Language Modeling Loss

```
L_CLM = - (1/T) Σ_t log P(x_t | x_{<t}; θ)
Perplexity = exp(L_CLM)
```

### 2.2 SFT Loss（Masked）

```
L_SFT = - Σ_{t ∈ assistant} log P(x_t | x_{<t}; θ)
```

### 2.3 DPO Loss

```
L_DPO = -E[log σ(β · (log π_θ(y_w|x)/π_ref(y_w|x) - log π_θ(y_l|x)/π_ref(y_l|x)))]

y_w = chosen, y_l = rejected, β = 温度系数, π_ref = 冻结的 reference model
```

### 2.4 Chinchilla Optimal

```
D_opt ≈ 20 × N

N = 参数量, D = 训练 token 数
```

### 2.5 显存估算

```
Training Memory ≈ Params × (2 + 2 + 8) bytes   [BF16: param + grad + Adam]
                + Activation(batch, seq, hidden, layers)
                + KV Cache (inference only)
```

### 2.6 有效 Batch Size

```
Effective Batch = per_device_batch × num_gpus × gradient_accumulation_steps
Effective Tokens  = Effective Batch × avg_seq_length
```

## 3. 训练阶段对比

| 维度 | Pretrain | CPT | SFT | DPO | GRPO |
|------|----------|-----|-----|-----|------|
| 数据 | 纯文本 | 领域文本 | 指令/轨迹 | 偏好对 | prompt + reward |
| 标注 | 无 | 无 | 有 | 有（成对） | 有（可验证） |
| Loss | CLM 全 token | CLM 全 token | CE mask assistant | Preference | Policy Gradient |
| LR | 1e-4~3e-4 | 1e-5~3e-5 | 1e-5~2e-5 | 5e-7~1e-6 | 1e-6~5e-6 |
| 计算量 | 极大 | 大 | 中 | 小 | 中~大 |
| 需 ref model | 否 | 否 | 否 | 是 | 可选 |

## 8. 常见问题 FAQ

**Q: Pretrain 和 CPT 有什么区别？**
A: 目标相同（CLM），CPT 是在已有 checkpoint 上继续，LR 更低，数据更聚焦。

**Q: SFT 和 Instruction Tuning 是一回事吗？**
A: 基本是。Instruction Tuning 强调指令格式数据，SFT 更广（含对话、tool use 等）。

**Q: DPO 能完全替代 RLHF 吗？**
A: 大多数场景可以。需要在线探索（如复杂 RL 环境）时 PPO 仍有优势。

**Q: LoRA rank 怎么选？**
A: 32 起步，64 常用，128 用于复杂任务。rank 越大可训练参数越多，但过拟合风险增加。

**Q: 为什么 SFT 后要做 DPO？**
A: SFT 只教「怎么做」，不教「哪个更好」。DPO 优化偏好，减少不安全/低质量输出。

**Q: 32K context 训练需要多少显存？**
A: 7B LoRA + Flash Attn + 1 batch ≈ 40G；32B Full + ZeRO-3 + 8 卡 ≈ 每卡 60~70G。

**Q: MFU 多少算正常？**
A: 单卡 A100 上 7B pretrain MFU 20~40% 常见；优化后 50%+ 算优秀。
