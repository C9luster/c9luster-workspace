# 08 — 会话持久化与恢复

## 日志是恢复单位

持久会话是仅追加的 `SessionEvent` 日志。模型请求、工具副作用和已完成步骤都先成为日志事件，再从日志投影出模型历史和客户端视图。产品默认后端是逐会话的 JSONL：不可变的规范 generation 文件名，后继文件排他发布，可选 Zstandard。已提交的 generation 路径不重命名、不替换、不删除。

版本按相邻链迁移。只读打开在内存中解码并迁移，不发布后继。写入打开在源文件旁发布下一版本命名的后继。未来版本被拒绝。未被后续事件封住的普通中断尾由句柄消费方修复；只有随后的 `turn/start` 已经封住一种已发布的重启时，迁移才补上缺失的 interrupted `turn/end`。

## 检查点策略

`dsh-session-checkpoint-policy` 决定何时必须把缓冲写入刷到存储。它不保存另一份图状态，也不增加提示词或工具。三个屏障：

| 时机 | 保证 |
|------|------|
| 模型请求构造流之前 | 响应到达前崩溃时，请求本身已经持久 |
| 顶层工具正文运行之前 | 可能产生外部副作用之前，调用已经持久。嵌套分派复用外层检查点 |
| 每个 `agent/pre-step` | 下一步派生请求之前，上一步的响应和有序工具结果已经持久 |

检查点失败则对应动作不开始。工具检查点等待期间若取消，返回 `ABORTED_BEFORE_DISPATCH`，不进入工具正文。步骤边界的刷新失败会使轮次失败。

工具检查点之后、结果到达之前的硬崩溃，会留下持久的未匹配调用。恢复时给出 `TOOL_OUTCOME_UNKNOWN`：只读或幂等调用可以重试，可能有副作用的调用需要核对状态或请用户确认。未完成的 Assistant 流保持瞬态，不自动重试。

后端本身仍有批处理窗口。不挂检查点策略时，日志格式仍可恢复，但窗口内尚未完成的写入可能丢失。

## 投影与标题

`ctx.sessionProjections` 把已提交事件增量折成当前值。`session-projection-cache` 持久化投影检查点，冷读不必扫描全量日志。轮次大纲和会话计数是两个投影单元。

标题从日志生成。没有 LLM 提供方时使用确定性回退。同时只能注册一个标题提供方，依据第一条合格人类消息或全部合格人类消息。

## 查询

`session-query` 是独立的读取面：有界读取、血缘、语义过滤，以及 SQLite 全文检索。它不替代日志写入路径。
