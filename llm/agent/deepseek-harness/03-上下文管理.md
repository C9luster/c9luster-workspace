# 03 — 上下文管理

## 会话日志即上下文来源

模型看到的历史由 `deriveMessages()` 从会话日志投影。新增模型可见输入需要会话事件。修改已有消息内容的插件注册纯消息投影；独立读取器传入相同处理器。

每个 `assistant/message` 嵌入产生该组装内容的紧凑流。失败、重试、取消和流错误以 `assistant/attempt` 留在日志中，不进入模型历史。进程在 settlement 之前硬中断时，不留下持久 attempt 流。实时 UI 增量来自 `agent/assistant-stream`。

运行时检查模型请求能否从日志重建。

## 系统提示词

`ctx.systemPrompt` 在每个模型步骤组装一份有序系统提示词，并附上当前工具 schema。贡献可以挂在全局，也可以挂在单个 Agent 的 `agent.ctx` 上；同名的 Agent 作用域贡献遮蔽全局默认值。

配置拥有固定开场白、是否包含 harness 身份、运行时上下文、部署 persona 的前缀与后缀，以及工具顺序。未解析变量或无效的完整组合会使组装失败，不会向模型发送格式错误的提示词。

动态事实由独立插件在步骤前注入，例如工作区指令、时间上下文和会话引用。注入经 `agent.inject()` 落入下一次获准的请求，并写入会话历史。

## 压缩

压缩是可选能力，不属于循环主干。`ctx.compaction` 是服务定义；`compaction-basic` 在 token 压力上升时把较早历史压成摘要；`/compact` 按需触发，并与运行中的轮次串行化。

压缩在日志中写入 `compaction/start`、`compaction/summary`、`compaction/end`。摘要对模型可见的表面变更，是一条带 `surfaceOp.replace` 的 `user/message`，遮蔽被替换区间。锁覆盖整次操作：中途崩溃表现为有 start 无 end，而不是虚假的完成标记。

配套能力：

| 包 | 作用 |
|----|------|
| `compaction-tool-result-pruner` | 修剪超大工具输出 |
| `compaction-image-offload` | 支持图片的路由拒绝请求时，把超出预算的图片换成占位文本 |

## Skills

`ctx.skills` 合并各提供方的目录，按名称选出胜出定义。`skill-filesystem` 从项目、自定义目录和用户目录发现技能并监视变更。`tool-skill` 把排序后的目录交给模型，并提供 `skill` 工具加载完整指令。用户在消息中以空白分界的 `/name` 调用同一份 `<skill_content>`。

目录在步骤前按已渲染条目的 digest 比较。digest 变化时追加一条持久的完整目录替换。压缩若隐藏了全部历史目录消息，下一份完整快照会重新建立当前目录。

已加载的指令正文作为工具结果留在后续步骤中，并随请求重发，直到被压缩遮蔽。压缩之后不会自动再写一份正文副本；模型若要再次使用正文，需要重新加载。相对资源按技能声明的 base 解析，只在需要时读取。

## 其它上下文

| 机制 | 作用 |
|------|------|
| Goal | 同一会话内持久目标，经 `ctx.goals` 在 `agent/*` 上续跑 |
| Session title | 基于日志生成标题，带确定性回退；同时只允许一个 LLM 标题提供方 |
| Spill | 超大工具输出外置到存储，请求中保留引用 |
