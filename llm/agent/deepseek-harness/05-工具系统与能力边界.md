# 05 — 工具系统与能力边界

## 注册与执行

工具注册到 `ctx.tools`。schema 进入当步系统提示词组装。执行经过防护流水线：

```text
tool/call
  → tools/pre-execute
  → tools/execute
  → tools/post-execute
  → tool/result
```

`tools/pre-execute` 与 `tools/post-execute` 是 waterfall。前置监听器可以拒绝或要求批准；后置监听器可以带反馈阻断结果，或向下游决策追加上下文。失败步骤会补上缺失的工具结果，避免请求里留下不成对的工具调用。检查点策略在顶层工具正文运行前刷新已记录的调用；嵌套分派复用外层检查点。

`maxParallelToolCalls` 限制并行安全调用的在途数量。独占调用单独执行。

## 执行世界

面向模型的工具是 Consumer，真正的读写和进程由服务提供方实现。

| Seam | 作用 |
|------|------|
| `ctx.fs` | 文件系统。文件工具与发现工具使用它 |
| `ctx.shell` | Bash 执行器。本地实现经 `ctx.subprocess` 拉起进程 |
| `ctx.terminals` | 限定所有者的持久 PTY |
| `ctx.sandbox` | 在启动进程前按策略包装 |
| LSP | stdio 提供方和 `lsp` 工具，跟随当前文件系统与进程世界 |
| `ctx.jobs` | 后台任务。`job_*` 工具读取或停止任务 |

把文件系统和进程提供方指到远程沙箱后，Bash、PTY 和 LSP 一起落在该世界上。

## Web、文档与附件

| 组 | 作用 |

| `deliverables` | 轮次交付物：显式交付的文件，以及记录下来的工作区改动 |

## MCP

`mcp-client` 连接已配置的 Model Context Protocol 服务器，将其工具与服务器指令接进原生工具面。`mcp-resources` 提供按服务器选择的资源发现与读取。只有作用域内存在已配置服务器时，模型才看得到对应工具和提示词。

## 循环卫生

`repeat-tool-reminder` 在模型重复完全相同的工具调用时写入提醒。`timeout-policy` 为声明了时限的调用返回超时错误。两者在 `dsh-base` 中默认启用。
