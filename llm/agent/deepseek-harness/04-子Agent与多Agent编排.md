# 04 — 子 Agent 与多 Agent 编排

## 编排模型

父 Agent 通过 `ctx.subagents` 把任务委派给子 Agent。面向模型的工具公布委派；`tool-subagent-control` 提供向相邻 Agent 发消息、中断工作和列出子级状态。父级可以看到正在运行的子级，也可以发现已经存储的子级。

子级后端注册到同一接口：

| 提供方 | 行为 |
|--------|------|
| 进程内新建 | 空白历史的子 Agent |
| 进程内 fork | 从父级已完成历史派生 |
| ACP | 进程外，走 Agent Client Protocol |
| Codex | 进程外，走官方 app-server |
| Claude Code | 进程外，走官方 Agent SDK |
| Harness SDK | 进程外，走 TypeScript SDK |

进程内驱动器由各提供方共享。同进程子级发出 `subagent/start` 与 `subagent/end`。可继续的子级接受后续轮次，而不是只返回一次性结果。委派深度大于零的子级不能使用定时提醒工具；Host 拒绝这类调用，避免提醒被投递到子会话。

## 父级与子级的边界

委派结果回到父级的会话，由父级决定下一步。子级使用自己的会话身份和工具面；fork 子级在起步时携带父级已完成历史。进程外后端的生命周期和权限遵循该后端产品，父级只看见该 seam 约定的终态。

## Agent Teams

`ctx.agentTeams` 是显式启用的协作 seam，建在可继续 subagent 之上，提供持久名册、任务板和邮箱。默认产品组合不自动开启该能力。

## 适用边界

| 更适合子级 | 更适合留在父级 |
|------------|----------------|
| 需要隔离上下文的一段工作 | 与用户确认、批准和最终汇报 |
| 要沿用父级已完成历史做分支探索 | 必须保持当前工具与权限面连续的步骤 |
| 交给 ACP、Codex 或 Claude Code 运行时执行 | 父级自己的计划与收束 |
