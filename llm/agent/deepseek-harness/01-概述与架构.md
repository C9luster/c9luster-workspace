# 01 — 概述与架构

## 定位

DeepSeek Harness（命令行产品名 `dsh`）是面向编码与通用任务的 Agent 运行时。模型适配器、工具、会话日志、沙箱、审批和 agent loop 都是插件。扩展方式是在配置树中挂载插件；插件卸载时撤销其注册。

底层框架是 Cordis：插件向共享上下文贡献服务、类型化事件和可逆副作用。服务以 `ctx.<name>` 暴露。扩展插件依赖 Service Definition，不依赖某个具体提供方。

## Profile 与组合包

一次运行的 `dsh` 是启动时按序叠加的插件树。

| 概念 | 含义 |
|------|------|
| Profile | Harness home 中的具名组装。列出组合包、已安装的树外插件和 `cordis.patch.yml` |
| 组合包 | Cordis 配置项及其挂载代码。上层 patch 可替换其中条目 |
| Patch | 按 id 替换某条目的整个 config，或插入新条目 |

随发行版交付的 profile 模板包括 `web`、`headless`、`sdk`、`sdk-minimal` 和 `acp`。`dsh-base` 是 `web`、`headless`、`sdk` 与 `acp` 的共享第一层，包含模型适配器、工具、持久化、沙箱、审批、设置、凭据与遥测。`sdk-minimal` 是独立的精简配置树，不套用 `dsh-base`。

叠加顺序：profile 列出的组合包、profile 的 `cordis.patch.yml`、home 级 patch、命令行 `--patch`。Node 应用通过 `dsh --profile <name>` 启动。Python SDK 默认启动同版本运行时的 `dsh --profile sdk`。

桌面应用携带匹配的生产运行时，使用保留的 `desktop` profile。默认 Host 端口为 `19387`。

## 能力 seam

一项可替换能力拆成三个角色：

| 角色 | 职责 |
|------|------|
| Service Definition | 声明接口 |
| Service Provider | 实现接口并注册 |
| Consumer | 使用接口，通常是面向模型的工具 |

文件系统与进程指向同一执行世界。更换远程沙箱提供方后，Bash、持久终端和 LSP 随之落在该世界上。Subagent 提供方实现同一委派接口，后端可以是进程内子 Agent，也可以是 ACP、Codex、Claude Code 或另一个 Harness 进程。

## 主干服务

| 服务 | 职责 |
|------|------|
| `ctx.sessions` | 每个 Agent 的仅追加会话事件日志 |
| `ctx.systemPrompt` | 有序提示词段、变量与工具 schema |
| `ctx.tools` | 工具注册表与带防护的执行流水线 |
| `ctx.agents` | `Agent` 句柄、实时注册表与 `agent/*` 事件 |
| `ctx.agentLoop` | 默认驱动器：创建 Agent 并运行轮次与步骤 |
| `ctx.llm` | 消息与流式词汇，以及提供方适配器 |

`dsh-agent` 是插件编程接口。`dsh-agent-loop` 是其默认实现，可以替换。
