# 05 — 持久化与关键能力

## Checkpoint：耐久执行的根基

路径：`libs/checkpoint/`（接口）+ `checkpoint-postgres` / `checkpoint-sqlite`（后端）

**Checkpoint** = 某一时刻图状态的快照。  
**CheckpointTuple** = checkpoint + config + metadata + pending writes。

### Thread

多租户 / 多会话靠 `thread_id` 隔离一条检查点链：

```python
config = {"configurable": {"thread_id": "1"}}
# 可选：从某一检查点续跑
config = {
    "configurable": {
        "thread_id": "1",
        "checkpoint_id": "0c62ca34-ac19-445d-bbb0-5b4984975b2a",
    }
}
compiled.invoke(input, config=config)
```

| 字段 | 含义 |
|------|------|
| `thread_id` | 会话 / 租户线程，必填（使用 checkpointer 时） |
| `checkpoint_id` | 线程内某次快照，可选 |

### Pending writes

同一步多个节点时，若其中一个失败：已成功节点的写会被记为 pending writes，resume 时不必重跑成功节点。这对「贵 / 有副作用」的节点很重要。

### 接口（实现者视角）

Checkpointer 需符合 `BaseCheckpointSaver`，核心方法包括：

- `put` — 存 checkpoint
- `get_tuple` / 列表查询 — 取历史
- `put_writes` — 存 pending writes
- 以及异步版本

开发可用内存实现（如 `InMemorySaver`）；生产用 Postgres / SQLite。

### Serde 注意

默认序列化能力较强。新应用建议收紧反序列化白名单（官方提示：`LANGGRAPH_STRICT_MSGPACK=true` 或显式 `allowed_msgpack_modules`），避免任意类型反序列化风险。

## Store：跨会话长期记忆

Checkpoint 偏「这一轮图怎么跑」；**Store** 偏「跨 thread 可检索的记忆 / 资料」。

典型分工：

| 层 | 存什么 |
|----|--------|
| Checkpoint | 当前图状态、下一步、中断点 |
| Store | 用户画像、知识片段、长期事实 |

## Human-in-the-loop

机制：执行到需要人工处 → `interrupt` → 图暂停且状态已 checkpoint → 人工审阅 / 改状态 → resume。

适用：

- 高风险工具调用确认
- 计划审批（plan 后再执行）
- 内容审核后再继续生成

没有 checkpointer，HITL 的「停得住、回得来」会大打折扣。

## Streaming

`stream` / `astream`（及事件级 API）可输出：

- 节点开始 / 结束
- 状态增量
- 消息 token / 消息块（与 messages 模式配合）

用于前端打字机效果、进度条、可观测性。对接 LangSmith 时可把轨迹完整串起来。

## 可靠性策略

节点级可配：

| 策略 | 用途 |
|------|------|
| `RetryPolicy` | 瞬态失败重试 |
| `CachePolicy` | 相同输入跳过重算 |
| `TimeoutPolicy` | 节点超时边界 |
| 节点 `error_handler` | 编译期默认可挂错误处理节点 |

这些在 `StateGraph` 的节点默认策略 / 单节点参数里配置（见 `graph/state.py` 中 `_NodeDefaults`）。

## 内存分层心智

```text
短时（本 turn / 本 thread）
  └─ Checkpoint + channel state（messages、中间结果）

长时（跨 thread / 跨天）
  └─ Store / 外部 DB / 向量库

瞬时（不落盘）
  └─ Ephemeral channel / 仅内存 config
```
