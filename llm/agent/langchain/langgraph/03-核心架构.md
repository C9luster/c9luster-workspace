# 03 — 核心架构

## 一句话

用户用 **StateGraph 建图**，`compile()` 得到可执行图；底层由 **Pregel** 按 **superstep** 调度节点，通过 **Channels** 合并状态写，可选挂上 **Checkpointer** 做持久化。

## 三层总览

```text
┌─────────────────────────────────────────┐
│  StateGraph（构建层）                      │
│  add_node / add_edge / compile            │
└──────────────────┬──────────────────────┘
                   │ compile()
                   ▼
┌─────────────────────────────────────────┐
│  CompiledStateGraph / Pregel（执行层）     │
│  invoke / stream / astream / ainvoke      │
│  superstep 调度、并行、重试、流式 IO        │
└──────────────────┬──────────────────────┘
                   │
        ┌──────────┴──────────┐
        ▼                     ▼
   Channels              Checkpointer
   (状态语义)             (快照 / 续跑)
```

## 1. StateGraph：构建层

路径：`libs/langgraph/langgraph/graph/state.py`

要点：

- `StateGraph` 是 **builder**，不能直接跑；必须 `.compile()`。
- 节点签名大致：`State -> Partial[State]`（也可注入 `Runtime` / config 等）。
- 状态字段可用 `Annotated[T, reducer]`：多节点写入同一 key 时用 reducer 聚合。
- 还支持 `context_schema`（运行期只读上下文，如 `user_id`）、`input_schema` / `output_schema`。

最小心智示例（来自源码 docstring 风格）：

```python
from typing_extensions import Annotated, TypedDict
from langgraph.graph import StateGraph


def reducer(a: list, b: int | None) -> list:
    if b is not None:
        return a + [b]
    return a


class State(TypedDict):
    x: Annotated[list, reducer]


graph = StateGraph(state_schema=State)
graph.add_node("A", node_fn)
# ... edges ...
compiled = graph.compile()
compiled.invoke({"x": 0.5})
```

`compile()` 之后得到 `CompiledStateGraph`，它本质是挂好 channel / 节点读写配置的 **Pregel 实例**。

## 2. Pregel：执行层

路径：`libs/langgraph/langgraph/pregel/`（`main.py` 体量很大，是运行时中枢）

职责包括：

| 职责 | 说明 |
|------|------|
| Superstep 调度 | 一轮激活若干节点，写回 channel，再进入下一步 |
| 并行执行 | 同一步可跑多个节点（配合 executor） |
| 读写通道 | 通过 read/write 组件访问 Channels |
| Checkpoint | 每步（或按策略）落盘状态与 pending writes |
| 流式 / 回调 | 对接 stream 模式与 LangChain callbacks |
| 重试 / 缓存 | `RetryPolicy`、`CachePolicy` 等 |

可以把它理解成「分布式图计算在单机 Agent 场景的精简版」：节点是 actor，channel 是邮箱 / 共享内存，checkpoint 是故障恢复点。

## 3. Channels：状态语义层

路径：`libs/langgraph/langgraph/channels/`

状态不是简单的「dict 整表覆盖」，而是 **每个 key 对应一种 channel 合并语义**。`StateGraph` 会根据 schema / annotation 选 channel（详见下一篇）。

常见类型：

| Channel | 语义（直觉） |
|---------|--------------|
| `LastValue` | 最后一次写入覆盖 |
| `Topic` | 多值主题 / 聚合 |
| `Delta` | 增量更新 |
| `EphemeralValue` | 临时、不跨步保留 |
| `NamedBarrierValue` | 命名屏障，等齐再放行 |
| `BinaryOperatorAggregate` | 用二元算子聚合（reducer 通道） |
| `UntrackedValue` | 不纳入某些跟踪 / 序列化路径 |

消息列表常用的 `add_messages`，就是在消息 channel 上做「追加 / 按 id 更新」类 reducer。

## 4. 控制流原语（执行时）

路径：`libs/langgraph/langgraph/types.py`

| 原语 | 作用 |
|------|------|
| `Send` | 动态向某节点投递一份输入（扇出 / map） |
| `Command` | 同时更新状态 + 指定下一步（或跳转） |
| `Interrupt` | 人机中断点相关类型 |
| `RetryPolicy` / `CachePolicy` / `TimeoutPolicy` | 节点级策略 |

这些让图从「静态边」扩展到「运行期动态拓扑」。

## 5. 另一条入口：func API

路径：`libs/langgraph/langgraph/func/`

用装饰器把普通函数编成工作流（`@entrypoint` / `@task` 一类），最终仍落到 Pregel。适合偏函数式、少显式画边的场景。

## 端到端数据流

一次典型 `invoke`：

```text
1. 用户传入 input + config（常含 thread_id）
2. Compiled graph 校验 / 映射到 input channels
3. Pregel 进入 loop：
   - 选出本步可运行节点
   - 执行（可并行）
   - 写 channel / pending writes
   - （可选）checkpointer.put
   - 发 stream 事件
4. 遇到 interrupt → 暂停，等待 resume
5. 到达 END → 按 output_schema 取出结果
```

## 读源码推荐顺序

1. `graph/state.py` — 图怎么建、compile 做了什么  
2. `types.py` — `Command` / `Send` / `Interrupt`  
3. `channels/` — 状态如何合并  
4. `pregel/_loop.py` / `pregel/main.py` — 真正怎么跑  
5. `libs/checkpoint/` — 快照如何存取
