# 07 — 选型对照与阅读路径

## 何时用 LangGraph

**适合：**

- 控制流复杂（分支、循环、子图、扇出）
- 需要耐久执行 / 失败续跑
- 需要 Human-in-the-loop
- 需要把「确定性流程」和「Agent 节点」混在一张图里
- 要对延迟、重试、缓存做节点级控制
- 生产级 Agentic：**LLM 在约束内逐步调度**，人设棋规与恢复

**不太适合作为第一选择：**

- 只要单轮工具调用 Demo，且零心智成本
- 完全无状态的一次性脚本
- 只想要托管聊天 UI、不想维护图与状态 / 策略

此时用 `create_agent` / Deep Agents 往往更快（底层仍可能是 LangGraph）。

## 常见形态对照

| 形态 | 代表 | 和 LangGraph 的关系 |
|------|------|---------------------|
| 轻 harness | `langchain.agents.create_agent` | 跑在 LangGraph 上 |
| 厚 harness | Deep Agents | agent harness，runtime 仍是 LangGraph |
| 手写图 | `StateGraph` | LangGraph 主战场 |
| 旧 prebuilt | `create_react_agent` | 弃用方向，迁 `create_agent` |
| IDE/终端 Coding Agent | Claude Code 等 | 栈不同；问题同构可对照 |

与 `llm/agent/claude-code` 对照：

| 概念 | Claude Code | LangGraph |
|------|-------------|-----------|
| 主循环 | Agentic Loop | Pregel superstep / ReAct 小图 |
| 会话恢复 | Transcript / Resume | Checkpoint / thread_id |
| 子任务 | Subagent / Swarm | 子图 / `Send` |
| 人工确认 | Ask / Plan Mode | `interrupt` + HITL |
| 工具 | Tool + MCP | ToolNode / 自定义节点 |

## 与 Miaoda / EntryPoint 对照（勿按类名硬映射）

| 你们 | 更像 LangGraph 生态哪一层 |
|------|---------------------------|
| Agent 循环 / 「无 tool_call 则 finish」 | Pregel / 条件边 / harness 主循环 |
| Event 转换 + 入库 / 回放 | stream events + transcript（偏账本） |
| Checkpoint 式可恢复状态 | Checkpointer |
| `MiaodaRuntime` / `CLIRuntime` | **工具执行环境 / sandbox**（不是图调度器） |
| Event → Hook（旁路） | callback / middleware（副作用），不一定等于下一跳 |

能力矩阵：

| 能力 | LangGraph 锚点 | 你们系统里找什么 |
|------|----------------|------------------|
| 主循环路由 | 条件边 / Command | tool_call 空则结束等规则 |
| 续跑 | Checkpoint | 任务/会话快照、resume |
| 展示与审计 | stream / 外部事件 | Event 入库 |
| HITL | interrupt | 审批流 |
| 工具落地 | ToolNode / 自定义节点 | Runtime、沙箱、工具注册 |
| 长期记忆 | Store | 用户资料 / 检索 |
