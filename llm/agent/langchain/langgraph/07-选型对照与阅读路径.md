# 07 — 选型对照与阅读路径

## 何时用 LangGraph

**适合：**

- 控制流复杂（分支、循环、子图、扇出）
- 需要耐久执行 / 失败续跑
- 需要 Human-in-the-loop
- 需要把「确定性流程」和「Agent 节点」混在一张图里
- 要对延迟、重试、缓存做节点级控制

**不太适合作为第一选择：**

- 只要单轮工具调用 Demo
- 完全无状态的一次性脚本
- 只想要托管聊天 UI、不想维护图与状态设计

此时用 prebuilt / LangChain agents / Deep Agents 往往更快。

## 与常见 Agent 形态对照

| 形态 | 代表 | 和 LangGraph 的关系 |
|------|------|---------------------|
| 预置 ReAct | `create_react_agent` | LangGraph 上的高层封装 |
| 手写状态机 / 工作流 | 自建 `StateGraph` | LangGraph 主战场 |
| IDE/终端 Coding Agent | Claude Code 等 | 产品级 Agent 循环；理念可对照，栈不同 |
| 多 Agent 框架 | CrewAI 等 | 编排哲学不同；LangGraph 更偏显式图与持久化 |

与本仓库其他笔记（`llm/agent/claude-code`）对照时，可抓住：

| 概念 | Claude Code 笔记里 | LangGraph 里 |
|------|-------------------|--------------|
| 主循环 | Agentic Loop | Pregel superstep loop |
| 会话恢复 | Transcript / Resume | Checkpoint / thread_id |
| 子任务 | Subagent / Swarm | 子图 / `Send` / 多节点 |
| 人工确认 | 权限 Ask / Plan Mode | `interrupt` + HITL |
| 工具 | Tool + MCP | ToolNode / 自定义节点 |

不是一一映射，而是**问题同构**：循环、记忆、权限、编排、持久化。

## 推荐阅读路径

### A. 只想会用（1–2 天）

1. 本目录 01、03、05  
2. 官方 Quickstart  
3. `create_react_agent` 跑通 + 加 memory checkpointer  
4. 看一个 `examples/human_in_the_loop`

### B. 要改源码 / 深度定制

1. 02 仓库地图  
2. `graph/state.py` → `types.py` → `channels/`  
3. `pregel/_loop.py` / `main.py`  
4. `libs/checkpoint` 接口与 Postgres 实现  
5. 对拍 `examples/multi_agent`、`subgraph`

### C. 要对齐公司 Agent 运行时（如 Miaoda / AgentOS）

按能力矩阵逐项对照，而不是按类名硬映射：

| 能力 | LangGraph 锚点 | 你们系统里找什么 |
|------|----------------|------------------|
| 状态与事件 | Channels + stream events | 会话状态、事件协议 |
| 续跑 | Checkpoint / pending writes | 任务快照、resume API |
| HITL | interrupt | 审批 / 确认流 |
| 工具执行 | ToolNode / 自定义节点 | Tool registry、沙箱 |
| 多 Agent | 子图 / Send | 子 Agent、编排器 |
| 部署 | CLI + SDK | 入口服务、网关 |
