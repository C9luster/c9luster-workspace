# 05 — 工具系统与能力边界

工具是模型的「双手」。Codex 的工具系统设计重点不在「工具数量」，而在：**统一路由、编排闸门、并行语义、以及 Direct vs Code Mode 两种暴露面**。

---

## 工具链路

```text
spec_plan::build_tool_router()
  → ToolRegistry（handler 注册）
  → ToolRouter（model_visible_specs + tool_mode）
  → ToolCallRuntime.handle_tool_call()
  → ToolOrchestrator（approval → sandbox → execute → retry）
  → 具体 handler（exec / patch / mcp / collaboration / …）
```

### ToolMode

| 模式 | 含义 |
|------|------|
| `Direct` | 模型直接看到各工具 schema |
| `CodeMode` | 可通过 Code Mode（JS/V8 worker）编排嵌套工具调用 |
| `CodeModeOnly` | 仅走 Code Mode dispatcher |

**亮点**：工具「有哪些」与「怎么被模型调用」分离——同一套 handler，可切换暴露策略；Code Mode 失败可受控回退。

---

## 内置能力一览

| 工具 / 面 | 用途 |
|-----------|------|
| `apply_patch` | 结构化补丁应用（独立 arg0 进程） |
| `exec_command` / `write_stdin` | Unified Exec：持久 shell、PTY、stdin 审批 |
| `mcp` + resource 相关 | MCP 工具与资源 |
| `spawn_agent` 等 | 多 Agent collaboration |
| `update_plan` | Plan 步骤跟踪 |
| `tool_search` | 动态工具发现 |
| `view_image` | 图像输入 |
| `request_user_input` | 向用户 elicitation |
| `request_permissions` | 运行时权限升级 |
| `new_context_window` / `get_context_remaining` | 上下文窗管理 |
| `request_plugin_install` | 插件安装建议 |
| `current_time` / `sleep` | 辅助 |

相对「Read/Edit/Bash 三件套」叙事：Codex 更强调 **patch 事务性** 与 **exec 会话性**。

---

## apply_patch：结构化改文件

- 独立 crate：`codex-rs/apply-patch`
- Streaming parser + 模糊匹配（`seek_sequence`）
- 经 `ExecutorFileSystem` + sandbox context 写盘
- 二进制自调用约定：`arg1 == --codex-run-as-apply-patch`（见 `codex-arg0`）

**亮点**：改文件不是「模型直接写任意字节」，而是走可解析、可校验、可沙箱的补丁语言——利于安全审查与失败回传模型。

---

## Unified Exec：会话化 Shell

- `ProcessManager`：持久 shell 进程池
- **Shell snapshot v2**：跨 turn 复用环境（减少每次冷启动）
- Stdin 写入可要求额外审批（长运行进程）
- `format_exec_output_for_model`：exit code、duration、截断策略统一

远程场景：`exec-server` + `EnvironmentManager` / `TurnEnvironment` 把同一套执行抽象接到容器或远端，而不是 UI 层 if-else。

---

## ToolOrchestrator：执行闸门

模块注释写明职责：

```text
approval → select sandbox → attempt → （denial 时）escalated sandbox retry
（审批缓存，避免重复询问）
```

还叠加：

- 网络策略 / deferred network approval
- Guardian 审查上下文
- 平台 `SandboxType` 选择

任何「能碰系统」的工具路径，最终应汇入这套语义——这是 Codex Agent 安全叙事的中枢。

---

## 并行执行

- 工具声明 `supports_parallel`
- `parallel_execution` 锁协调：不安全并行的工具串行
- PreToolUse / PostToolUse hooks 挂在工具生命周期上

模型可一次发多个 tool call；运行时按安全性调度，而不是无脑 Promise.all。

---

## MCP

- `McpManager`：聚合 config servers + plugin connectors + extension contributions
- 按环境的 authority（`McpEnvironmentAuthority`）
- `McpRefresh`：刷新序列化，不阻塞已捕获的调用
- `mcp_tool_exposure` 控制暴露面

Mentions 可驱动「本 turn 需要哪些 server」——按需拉起，而不是启动时全开。

---

## Code Mode（特色能力）

- crates：`code-mode`, `code-mode-host`, `code-mode-runtime`, `code-mode-protocol`
- 模型用小型程序编排多次工具调用（V8 worker）
- 适合「分支逻辑多、要在工具间编程式粘合」的任务
- 与 Direct 模式 runtime 分离，降低工具 schema 爆炸时的模型负担

---

## 工具 vs Skill vs Hook

| 机制 | 谁触发 | 作用 |
|------|--------|------|
| Tool | 模型 function call | 实际副作用 |
| Skill | `@skill` 或隐式匹配 | 注入专业指令 / 流程（正文进本轮 user 槽，见 [07](./07-扩展机制.md)） |
| Hook | 生命周期事件 | 拦截、改写、阻断、追加 context |

Skill 不替代 Tool；Hook 不替代权限系统——三者叠在 Orchestrator 前后。

---

## 设计亮点小结

1. **Router + Orchestrator 两段式**：可见性与执行策略分离  
2. **apply_patch 事务感**：改文件可解析、可沙箱  
3. **Exec 会话化**：snapshot、PTY、stdin 审批  
4. **并行有声明**：`supports_parallel` 而非默认全并行  
5. **Code Mode**：用程序结构压缩复杂工具编排  
6. **协作工具不进 exec 命名空间**：能力边界写进 schema
