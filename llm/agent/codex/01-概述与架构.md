# 01 — 概述与架构

## 一句话定义

Codex 是 OpenAI 的**本地 Agentic Coding System**。它以 Rust 实现的 `codex-core` 为业务内核，通过 CLI / TUI / Exec / App-Server 等多种入口，在真实项目目录中读代码、改文件、跑命令，并用平台级沙箱与审批策略约束能力边界。

## 技术定位：三个关键词

| 关键词 | 含义 |
|--------|------|
| **Local-first Agent** | 主循环跑在本机（或本机连接的 exec 环境），不是纯云端聊天 |
| **Protocol-separated** | UI 与 Agent 内核通过 App-Server 协议解耦，同一 Core 服务多种前端 |
| **Security-native** | 沙箱、ExecPolicy、审批、Guardian 不是外挂，而是工具执行路径的内建闸门 |

## 与同类工具的架构差异

| 工具 | 架构模式 | 运行位置 | 工具执行 |
|------|----------|----------|----------|
| **Codex** | Core + App-Server + 多前端 | 本地进程 / daemon | 沙箱化 Shell + apply_patch + MCP |
| Cursor / Copilot | IDE-integrated | IDE 进程内 | LSP / IDE API |
| Aider | CLI chat → git patch | 本地进程 | 文件/补丁为主 |

核心差异：Codex 把 **Agent 业务（core）** 与 **交互面（tui/cli/ide）** 严格拆开——`codex-core` 甚至禁止 `print_stdout`，所有对外可见行为都经事件/协议回流。这使同一套 Agentic Loop 可被 TUI、无头 Exec、VS Code 扩展、桌面 App 复用。

## 它不是什么

- **不是单纯的 ChatGPT CLI 包装**：有完整 Session/Turn、工具编排、沙箱、持久化
- **不是「无沙箱 Shell 代理」**：默认走平台沙箱 + 审批；危险路径可 fail-closed
- **不是只服务一种 UI**：默认进 TUI，但 `exec`、app-server、IDE 共用 Core
- **不是无状态单次补全**：Thread / Rollout 可 Resume、Fork、Revert

## 分层架构

Codex 从上到下可看成五层（交互入口 → 协议 → 编排 → 运行 → 持久化），并多了一层显式 App-Server 协议：

| 层次 | 职责 | 关键词 / 典型 crate |
|------|------|---------------------|
| **入口层** | 参数解析、认证、选择交互形态 | `cli`, `tui`, `exec` |
| **协议层** | JSON-RPC：thread/turn 生命周期 | `app-server`, `app-server-protocol`, `app-server-daemon` |
| **编排层** | Thread/Session、输入准入、任务调度 | `core`：`ThreadManager`, `Session`, `turn_input` |
| **运行层** | 采样循环、工具、沙箱、远程执行 | `core/session/turn`, `tools`, `sandboxing`, `exec-server` |
| **持久化层** | Rollout、索引、Agent 拓扑 | `rollout`, `thread-store`, `agent-graph-store` |

### 端到端数据流

一次典型用户请求（例如「修复编译错误」）的完整路径：

```text
1. 入口层
   codex → CLI Multitool → 默认启动 TUI（或 exec / app 子命令）

2. 协议层
   TUI / IDE 经 App-Server：thread/start 或 thread/resume → turn/start

3. 编排层（Session）
   turn_input 判定：Start | Steer | Reject
   → 创建 TurnContext，派发 RegularTask

4. 核心循环（run_turn）
   预压缩 / Hooks / WorldState diff
   → 组装 Prompt → 流式采样
   → tool_use → ToolOrchestrator（审批→沙箱→执行）
   → 结果回写历史 → 需要则继续采样

5. 工具 / 执行层
   apply_patch / unified exec / MCP / collaboration.* / Code Mode

6. 持久化层
   Rollout JSONL 追加 + state_db 索引；TurnComplete 事件回 UI
```

### 关键对象链

```text
ThreadManager
  └─ CodexThread          # 对外线程句柄
       └─ Session         # 单线程运行时（≤1 active turn）
            └─ TurnContext   # 回合级：模型、权限、环境
                 └─ StepContext  # 单次 sampling：ToolRouter、MCP binding
```

### 典型 Agentic Loop 示例

| Turn 内 Step | AI 决策 | 工具调用 | 结果 |
|------|---------|----------|------|
| 1 | 先看错误 | `exec_command` 跑 build | 编译器 stderr |
| 2 | 定位文件 | 读文件 / 搜索 | 源码片段 |
| 3 | 改代码 | `apply_patch` | 结构化补丁落盘 |
| 4 | 验证 | 再跑 build / test | 通过或继续修 |

每一步都是模型自主决策；Codex 负责**准入、上下文、审批、沙箱、持久化**，而不是替模型写死步骤。

## 四种核心设计原则

### 1. Core 与 UI 解耦（Protocol-first）

- 业务逻辑集中在 `codex-core`；前端只消费事件与 RPC
- App-Server 成为 IDE / 桌面 / CLI 的稳定集成面
- 无头 `exec` 可内嵌 InProcess App-Server Client，不必另写一套 loop

### 2. Turn 准入先于副作用（Admission-first）

- `turn_input.rs` 明确：先判定 Start / Steer / Reject，再回复调用方
- **不等待** user-prompt hooks、完整持久化或采样完成才给决策回执
- 被 Reject 的输入不提交 thread settings，避免脏状态

### 3. 工具执行必经闸门（Orchestrated Capability）

- `ToolOrchestrator`：approval → select sandbox → execute → denial 时升级重试
- 审批结果可缓存，避免同策略反复打断用户
- 多 Agent 协作工具放在独立 `functions.collaboration.*` 命名空间，禁止经 `exec` 偷渡

### 4. 上下文是结构化状态（WorldState as Memory）

- 权限、工具表、AGENTS.md、协作模式等是 WorldState sections；可选 **Memories** 做跨 chat 召回  
- 按 diff 注入；Compaction 替换 model window，但 retained facts / Guardian 根消息可跨压缩保留

## 三种（及以上）交互形态

| 形态 | 是什么 | 使用方式 | 典型场景 |
|------|--------|----------|----------|
| **TUI** | 终端交互 UI（Ratatui） | 直接 `codex` | 日常多步编码 |
| **Exec** | 无头一次性/脚本模式 | `codex exec "..."` | CI、管道、自动化 |
| **App-Server** | JSON-RPC 服务（可 daemon） | IDE / `codex app` / 外部客户端 | 编辑器与桌面集成 |
| **MCP Host** | 把 Codex 能力暴露/消费 MCP | `codex mcp` 等相关子命令 | 工具生态互操作 |

「程序化接入」重心在 **App-Server 协议** 与 **exec 事件流**，同一 Core 服务多种前端，而不是为每种 UI 再维护一套平行 Agent 实现。

---

## 为什么选择 Rust Core + 多前端

- **性能与安全边界**：沙箱辅助进程、长时间会话、严格的 deny lint（core 不打 stdout）
- **同一内核多产品形态**：CLI、IDE、Cloud Tasks、桌面 App 共享行为语义
- **可测试的协议面**：app-server 集成测试覆盖 thread resume、turn 生命周期等

代价：crate 数量多（`codex-rs` workspace 规模很大），学习曲线在「协议 + 安全纵深」而不在「写个脚本调 API」。
