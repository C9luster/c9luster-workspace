# 03 — 上下文管理

Codex 的上下文工程核心不是「把尽量多的文字塞进 system prompt」，而是：**结构化 WorldState + 双轨历史 + 可控 Compaction**。在有限 token 窗口内维持工作记忆、项目约定与跨压缩事实。

---

## 双轨历史模型（设计亮点）

`ContextManager` 把「给模型看的窗口」和「Host 要保留的事实」拆开：

| 轨道 | 内容 | Compaction 时 |
|------|------|----------------|
| **Model window** | `items`：发给模型的 transcript | 可被 summary 替换 |
| **Retained context** | Host 侧事实（独立于 model window） | 跨压缩保留 |
| **reference_context_item** | 下一回合 diff 的基线 | `None` 时倾向全量 reinject |
| **world_state_baseline** | 上次写入历史的 WorldState 快照 | 用于算 diff |
| **history_version / user_message_revision** | 压缩代际 vs 用户输入代际 | Guardian 授权等场景使用 |

**亮点**：压缩只替换 model window；Guardian root messages、retained facts 可原子快照保留——避免「一压缩就丢安全根上下文」或「每次把整份 AGENTS.md 再贴一遍」。

---

## WorldState：按 Section 增量注入

WorldState 由多个 **Section** 组成，每 turn 做 **diff**，而不是全量重发：

| Section（示例） | 内容 |
|-----------------|------|
| `AgentsMdState` | 项目 AGENTS.md 链 |
| `EnvironmentsState` | 环境 / CWD |
| `PermissionsState` | 权限配置 |
| `ToolsState` | 工具列表 |
| `MultiAgentModeState` | 多 Agent 模式说明 |
| `PluginsInstructionsState` | Plugin 指令 |
| `CollaborationModeState` | Plan / Default 等协作模式 |
| `ModelInstructionsState` | 模型切换说明 |
| 其他 | personality、realtime、apps 等 |

Extension 可通过 `ContextContributor` / `WorldStateSectionContribution` 注入自定义 section。

```text
上一回合 baseline
        ↓ diff
仅变化的 section → 写入历史为 context items
        ↓
Prompt = history(model window) + base instructions + 增量事实
```

相对「每轮重拼超长 system prompt」：稳定部分不重复占窗，变化部分可审计、可测试。

## AGENTS.md：项目记忆约定

发现与拼接逻辑（`agents_md.rs`）：

1. 从 CWD 向上找 project root（默认 marker：`.git`）
2. 沿 root → CWD 路径收集 `AGENTS.md` 与 `AGENTS.override.md`
3. 与 user instructions 拼接（分隔标记如 `--- project-doc ---`）
4. 受 `project_doc_max_bytes` 限制；**untrusted project** 可跳过

Base instructions 里也会内嵌 AGENTS.md 使用规范（协议侧 prompts）。TUI `/init` 可引导生成项目文档。

**AGENTS.md 是文件系统上的项目宪法**：由运行时发现并经 WorldState 注入，而不是只靠聊天里口头约定。用户级还可存在 `~/.codex/AGENTS.md`（随 CODEX_HOME），与仓库内文档分层叠加。

## Memories：跨会话自动记忆（可选）

与 AGENTS.md（显式、可入库）互补，Memories 是 **本地自动沉淀的跨 chat 召回层**。官方建议：必须遵守的团队规则仍放 AGENTS.md / 仓库文档；Memories 只作辅助，不当唯一真理源。

### 开关与控制

- Feature 默认 **关闭**；配置示例：`[features] memories = true`
- TUI **`/memories`**：控制**当前 chat** 是否使用已有记忆、是否可作为未来记忆生成输入（不改全局开关）
- 相关配置：`memories.use_memories`、`memories.generate_memories`、脱敏/外部上下文跳过、rate-limit 门槛、抽取/合并模型覆盖等（见配置参考）

### 存储与生成

- 目录：默认 `~/.codex/memories/`（受 `CODEX_HOME` 影响）
- 内容含摘要、durable entries、近期输入、rollout 证据等；视为 **生成态**，排查可看，不建议手改当主控面
- 在合格会话 **空闲足够久** 后后台抽取/合并；可跳过过短或仍活跃会话；可对生成字段脱敏
- 启用后可通过 Memory 相关工具检索；响应可带 **memory citation**

### 与会话连续性的关系

| 机制 | 跨什么 | 性质 |
|------|--------|------|
| AGENTS.md | 项目/用户指令 | 显式、常驻注入 |
| Memories | 多 chat 沉淀事实/偏好 | 可选、后台生成 + 召回 |
| Rollout / Resume | 同一 Thread | 会话世界线续跑 |
| Compaction + retained / WorldState | 同一 Thread 压缩后 | 保住世界事实，非整份聊天原样 |

## Token 预算与窗口

| 机制 | 作用 |
|------|------|
| `context_window` / token 估算 | 判断是否接近上限 |
| `token_budget` / auto compact limit | 触发预压缩或 mid-turn 压缩 |
| `rollout_budget` | 会话体量提醒（与持久化相关） |
| `get_context_remaining` 工具 | 模型可主动查询余量 |
| `new_context_window` 工具 | 手动开新上下文窗（产品能力） |

预采样压缩（PreTurn）与中途压缩（MidTurn）触发时机不同，**initial context 注入策略也不同**（见下节）。

---

## Compaction 策略

触发来源：

| 触发 | Phase | InitialContextInjection |
|------|-------|-------------------------|
| Token 将超限（回合前） | PreTurn | `DoNotInject`（交给后续全量/基线 reinject） |
| Token 超限（回合中） | MidTurn | `BeforeLastUserMessage`（summary 落在最后 user 消息前） |
| 手动 `/compact` | Manual | 按路径注入 |
| Remote compaction | Auto/Manual | 服务端压缩 + 图像 budget 等 v2 能力 |

`InitialContextInjection` 的注释揭示训练/产品约束：

- Mid-turn 压缩后，模型被训练为「看到 compaction summary 作为历史中的特定位置」
- 因此 mid-turn 必须用 `BeforeLastUserMessage`，把 initial context 插到最后一条真实 user message 之上

流程概览：

```text
run_pre_compact_hooks
  → 模型 summarization（或 remote compact）
  → replace_compacted_history
  → run_post_compact_hooks
  → 写入 ContextCompactionItem checkpoint（持久化）
```

**亮点**：Compaction 与 WorldState reinject 解耦——压缩算法负责缩小 transcript；「世界事实」由 injection 枚举精确控制，避免 summary 丢掉权限/工具面后行为漂移。

## Skills / Plugins / Mentions 对上下文的影响

回合前还会：

- 解析 `@skill` / connector / plugin mentions
- 按需启动 MCP server
- `build_skills_and_plugins` 生成注入项
- 显式 skill invocation 事件

这些都进入「本 turn 可见上下文」，但通过结构化注入与工具面绑定，而不是散落在无类型字符串里。Skill 的 `@` 注入细节见 [07-扩展机制](./07-扩展机制.md)。

---

## 设计亮点小结

1. **双轨历史**：模型窗可扔，Host 事实可留  
2. **WorldState Diff**：上下文是状态机，不是作文  
3. **Injection 枚举**：压缩相位决定 reinject 位置，对齐模型训练假设  
4. **AGENTS.md 链**：从 repo root 到 CWD 的分层项目记忆  
5. **Memories（可选）**：跨 chat 本地沉淀与召回  
6. **扩展可贡献 section**：插件与核心共享同一上下文模型
