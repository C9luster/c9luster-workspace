# 09 — 特性与模式索引

本章索引 Codex 在 Agent 层面的主要模式与特性，便于对照实现与产品行为。Feature 多由配置、`codex_features::Feature`、模型目录能力与实验开关共同门控。

---

## 核心 Agent 模式

### Multi-Agent V2

| 项 | 说明 |
|----|------|
| 入口 | `spawn_agent` 等 `functions.collaboration.*` |
| 根身份 | `/root` |
| 上下文 | `fork_turns`：none / 整数 / all |
| 通信 | NEW_TASK / MESSAGE / FINAL_ANSWER |
| 约束 | 不可经 `functions.exec` 调用协作工具 |
| 持久化 | Agent Graph + 子 Thread Rollout |
| 典型场景 | 并行调研与实现、角色化分工 |

详见 [04-子Agent与多Agent编排](./04-子Agent与多Agent编排.md)。

### Collaboration Mode：Plan vs Default

| 项 | 说明 |
|----|------|
| 枚举 | `ModeKind::Plan` / `Default` |
| Plan | 规划优先；限制 Automatic turn 启停 |
| Default | 常规执行（别名曾含 code/execute 等） |
| 工具 | `update_plan` 等 |
| 典型场景 | 先方案后改代码；与审批策略叠加 |

详见 [06-安全权限与Plan-Mode](./06-安全权限与Plan-Mode.md)。

### Code Mode

| 项 | 说明 |
|----|------|
| ToolMode | `Direct` / `CodeMode` / `CodeModeOnly` |
| 运行时 | V8 worker 编排嵌套工具调用 |
| 价值 | 复杂分支逻辑不必全靠自然语言连环 tool_use |
| 回退 | 与 Direct 分离，可受控 fallback |

详见 [05-工具系统与能力边界](./05-工具系统与能力边界.md)。

### Guardian / AutoReview

| 项 | 说明 |
|----|------|
| ApprovalsReviewer | `User` / `AutoReview` |
| 形态 | 旁路审查会话，有界超时 |
| 覆盖 | exec / network / MCP / 升级等 |
| 典型场景 | 减少琐碎人工审批，同时保留风险框架 |

### Remote / Exec Server 环境

| 项 | 说明 |
|----|------|
| 抽象 | `EnvironmentManager` / `TurnEnvironment` |
| 传输 | exec-server protocol |
| 能力 | 远端 shell、FS、sandbox、capability roots |
| 典型场景 | IDE 连容器、Wine exec 测 Windows、云端任务 |

### Unified Exec + Shell Snapshot

| 项 | 说明 |
|----|------|
| 能力 | 持久 shell、PTY、stdin 审批 |
| Snapshot v2 | 跨 turn 复用环境 |
| 典型场景 | 长会话少冷启动；交互式命令流 |

### apply_patch

| 项 | 说明 |
|----|------|
| 形态 | 结构化补丁语言 + 独立进程 |
| 沙箱 | 经 ExecutorFileSystem 强制策略 |
| 典型场景 | 可靠改文件，便于失败回传模型 |

## 入口与集成模式

| 模式 | 入口 | Agent 行为差异 |
|------|------|----------------|
| TUI | `codex` | 完整审批 UI、slash、多 Agent 可视 |
| Exec | `codex exec` | 无头；事件/最终输出；常配严格/Never 审批 |
| App-Server | daemon / in-process | IDE/App 集成；thread/turn RPC |
| MCP | mcp 子命令/服务器 | 工具生态互操作 |

详见 [02-交互形态与Agentic-Loop](./02-交互形态与Agentic-Loop.md)。

## Agent 设计「优秀之处」总表

验收视角下，Codex 值得学的不是单点技巧，而是组合：

| # | 亮点 | 为何优秀 |
|---|------|----------|
| 1 | Core / UI 协议分离 | 一种 Agent 语义，多种产品形态 |
| 2 | Turn 准入 Start/Steer/Reject | 消除交互竞态，Plan 可强制 |
| 3 | TurnContext / StepContext | mid-turn 变更与采样快照不互相污染 |
| 4 | WorldState Diff | 上下文可测试、少重复、可扩展 |
| 5 | ToolOrchestrator | 审批+沙箱+重试一个漏斗 |
| 6 | 沙箱 fail-closed | 安全语义诚实 |
| 7 | Guardian 旁路 | AI 审批不污染主任务 |
| 8 | collaboration 命名空间 | 多 Agent 原语不可经 shell 伪造 |
| 9 | fork_turns | 上下文遗传显式权衡 |
| 10 | Code Mode | 工具编排可编程 |
| 11 | Skills 隐式触发 | 工艺知识跟命令走 |
| 12 | Explicit `@skill` 全文注入 | 选中即进本轮 user 槽 |
| 13 | Rollout + Graph Resume | 长程与多 Agent 可恢复 |
| 14 | Memories（可选） | 跨 chat 本地沉淀与召回 |
