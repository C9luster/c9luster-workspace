# 08 — 会话持久化与恢复

Codex 的本地会话核心是 **Rollout（JSONL，可压缩）+ ThreadStore + state_db 索引**。持久化决定 Agent 跨进程、跨 compact、跨多 Agent 拓扑恢复后「还是不是同一个世界」。

---

## 核心不变量

| 不变量 | 含义 |
|--------|------|
| Rollout 以追加为主 | 会话事件/条目顺序写入，压缩有 checkpoint 语义 |
| Thread 是恢复单位 | resume 按 thread/rollout 重建 Session |
| Compaction 留痕 | 替换 model window，同时持久化 compaction metadata |
| 多 Agent 有图 | Graph Store 恢复 parent/child metadata |
| Fork 有明确快照语义 | 截断点 / interrupted 标记与真实中断对齐 |

---

## 系统分层

```text
磁盘层：Rollout JSONL（可选 zstd）+ SQLite state_db
  → 存储抽象：ThreadStore（create/read/append/resume/fork/revert）
  → 运行重建：ThreadManager → Session + ContextManager
  → 协议暴露：app-server thread/resume 等
  → UI：TUI /resume、exec --resume
```

---

## Rollout

- 路径概念上位于 `$CODEX_HOME/sessions/`（实现细节以 thread-store/rollout 为准）
- 行结构近似：`RolloutLine { timestamp, ordinal, item }`
- `RolloutRecorder` 异步写入
- `PersistContext` 区分 Standard / TurnStart / CompactionCheckpoint 等——**精确控制何时落盘**，避免 compact 与 turn 边界竞态

---

## ThreadStore

抽象接口能力：

| API（概念） | 作用 |
|-------------|------|
| `create_thread` | 新世界线 |
| `read_thread` / `append_items` | 读与追加 |
| `resume_thread` | 从历史恢复 |
| `prepare_fork` | 准备分叉 |
| `revert_thread` | 回退 |

本地实现：`LocalThreadStore` = rollout 文件 + state_db。

---

## Resume 流程

```text
resume_thread_from_rollout(path)
  → InitialHistory::Resumed
  → restore_v2_agent_metadata（多 Agent）
  → start_thread_inner() 重建 Session + ContextManager
  → 首事件 SessionConfigured
```

TUI `/resume` 与 `exec --resume` 都走协议层 `thread/resume`，保证交互/无头语义一致。

---

## Fork 语义

`ForkSnapshot` 一类枚举（概念）：

| 变体 | 含义 |
|------|------|
| 截断到第 n 条 user message 前 | 「从对话某点另开世界线」 |
| Interrupted | 模拟 interrupt 后的 aborted 标记，与真实中断行为一致 |

**亮点**：Fork 不是简单拷贝文件；它编码了**与运行时中断相同的标记**，避免恢复后模型看到自相矛盾的 transcript。

---

## Compaction 与持久化

- 压缩后写入 `ContextCompactionItem` / checkpoint
- live history 与 persisted history 在赋 ID 后保持一致（`replace_compacted_history` 路径）
- Remote compact v2 还可处理图像 budget 等服务端语义

模型窗变了，但 Rollout 仍能讲述「何时压缩、压缩成什么」——利于调试与审计。

---

## 多 Agent 恢复

- Agent Graph Store 存边与状态
- Resume 时恢复 V2 agent metadata
- 子 thread 各自 rollout；父侧保留协作关系而非只留一句「子任务完成」

---

## 设计亮点小结

1. **存储抽象 ThreadStore**：UI 不直接搓文件格式  
2. **PersistContext**：compact/turn 边界写入可推理  
3. **Fork = 语义快照**：含 interrupted 对齐  
4. **Graph + Rollout**：多 Agent 可恢复不只是单会话  
5. **多前端同一 resume 协议**：TUI/Exec/IDE 行为一致
