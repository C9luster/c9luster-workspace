# 07 — 扩展机制

Codex 的可扩展性围绕四条主线：**Skills**、**Hooks**、**Plugins / Extension API**、**MCP / Connectors**。它们把「改 Core」变成「在生命周期点上贡献行为」。

---

## Skills

### 形态

- `SKILL.md`：frontmatter 元数据 + 指令正文
- 作用域：`user` | `repo` | `system` | `admin`
- 系统 skills 可嵌入二进制，指纹缓存到 `CODEX_HOME/skills/.system`

### 触发路径

| 类型 | 触发 | 行为 |
|------|------|------|
| **Explicit** | `@skill` / `$name` 等 mention | **当轮注入**选中 skill 的正文 |
| **Implicit** | shell 命令 pattern 匹配 | `detect_implicit_skill_invocation` 识别/打点；不等于再自动灌全文 |

### Explicit `@` 如何进入 LLM 请求

回合前 `build_skills_and_plugins` / Skills Extension 的 turn input contributor 会：

1. 解析用户输入中的 skill mentions  
2. 读取该 skill 主提示（通常 `SKILL.md` 正文；过长截断并告警）  
3. 生成结构化 turn 注入片段（本轮采样可见）

典型形态：

```text
developer 角色片段：
  Skills 目录 / 用法说明（可用 skill 列表 + 短描述/路径）

user 角色片段：
  <skill>
  <name>demo</name>
  <path>.../SKILL.md</path>
  …SKILL.md 正文…
  </skill>
```

要点：

- 正文进 **协议上的 user 槽**，与用户本轮 query **同一次采样请求**可见  
- 通常是 **独立 fragment**，不是把 md 简单拼进用户原句同一个字符串  
- System/developer 侧另有 **目录级** listing，不是把所有 skill 全文常驻  
- 还可经 Skill 工具按需再读资源

**亮点**：Skill 不只是「用户手册片段」，可与命令模式绑定（implicit）——模型一跑某类命令，相关工艺知识可自动就位（invocation 路径与 explicit 全文注入不同）。

## Hooks（12 类事件）

典型事件集合：

```text
PreToolUse, PermissionRequest, PostToolUse,
PreCompact, PostCompact,
SessionStart, SessionEnd,
UserPromptSubmit,
SubagentStart, SubagentStop,
Stop, Interrupt
```

Hook 可（**白名单能力，非任意改 event content**）：

- **block** turn / 工具
- 注入 `additional_context`
- **PreToolUse**：`updatedInput` 重写工具入参（配合 allow）
- 触发或配合 compaction；Stop 可注入 continuation

**不支持或 fail-closed**：改写用户 prompt 正文、PostToolUse 改工具输出（`updatedMCPToolOutput` 当前 unsupported）、PermissionRequest 携带 reserved 的 `updatedInput` 等。

异步 Hook 结果经 channel 在 turn 边界 `drain`——与「Turn 准入先回复」一致：不把异步副作用堵在 RPC 回执临界区。

Project hooks 与 Plugin hooks 合并 dispatch。

## Plugins 与 Extension API

Contributor 体系（`ext/extension-api`）示例：

| Contributor | 贡献点 |
|-------------|--------|
| `TurnLifecycleContributor` | Turn 生命周期 |
| `ThreadLifecycleContributor` | Thread 生命周期 |
| `ToolContributor` | 注册工具 |
| `McpServerContributor` | MCP server |
| `ContextContributor` | WorldState / 上下文 |
| `SkillInvocationContributor` | Skill 调用 |
| `SynchronousApprovalReviewer` | 审批审查（Guardian V2 等） |

`PluginsManager`：marketplace 加载、connector 注册、turn usage 追踪。

**亮点**：扩展面是 **类型化 contributor**，而不是「随便 hook 全局单例」——与 WorldState section、ToolRouter 同一架构语言。

## MCP 与 Connectors

- 配置文件声明 MCP servers
- Plugin / extension 可贡献 server
- Apps / connectors 快照与工具策略评估（`AppToolPolicyEvaluator` 等）
- Mentions 驱动本 turn 依赖安装提示（`maybe_prompt_and_install_mcp_dependencies`）

## Slash Commands（TUI）

80+ 命令，按使用频率排序（非纯字母序），覆盖 Agent 操作面：

`/model`、`/permissions`、`/compact`、`/resume`、`/fork`、`/review`、`/skills`、`/hooks`、`/mcp`、`/plugins`、`/agents`、`/plan`、`/init`…

斜杠命令是**用户操作协议**，底层仍落到 Session / ThreadStore / Hooks 等同一 Core。

## 扩展如何嵌进 Agentic Loop

```text
SessionStart hooks
  → TurnStart hooks / skill&plugin 注入
  → sampling
  → PreToolUse → Orchestrator → PostToolUse
  → （可选）PermissionRequest / Guardian
  → PreCompact / PostCompact
  → Stop / SubagentStop
  → SessionEnd
```

扩展点环绕 loop，而不复制 loop。

## 设计亮点小结

1. **Contributor 模型**：扩展与 Core 同构  
2. **Skill 双触发**：显式 `@` 全文注入与隐式命令模式  
3. **Hook 异步边界清晰**：不破坏 Turn 准入延迟目标；能力白名单约束（见上文 Hooks）  
4. **审批也可扩展**：SynchronousApprovalReviewer  
5. **用户面 slash = Core 能力投影**：避免 UI 私有逻辑分叉
