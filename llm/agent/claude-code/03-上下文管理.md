# 03 — 上下文管理

Claude Code 的上下文工程是 Agent 能力的核心：如何在有限 token 窗口内维持「工作记忆」、项目知识和对话连续性。本章涵盖 System Prompt 组装、Token 预算、三层压缩策略、项目记忆系统。

---

## 上下文窗口与有效空间

默认上下文窗口 200K tokens，但**实际可用于对话的空间远小于此**：

```text
上下文窗口（200K）
├── 系统提示词（~15-25K，缓存后成本低）
├── 工具定义（~10-20K，含 MCP）
├── 用户上下文（CLAUDE.md、git status 等）
├── 输出预留（maxOutputTokens）
│   ├── 默认上限：64K
│   ├── 实际默认：8K（slot-reservation 优化）
│   └── 触顶自动升级：一次 64K 重试
└── 剩余：对话历史空间（随对话增长）
```

**有效上下文** = 窗口大小 - min(maxOutputTokens, 20K)（压缩摘要需预留输出空间）。

### 窗口大小解析优先级

1. CLAUDE_CODE_MAX_CONTEXT_TOKENS 环境变量
2. 模型名含 [1m] 后缀 → 1M
3. 模型 capability 的 max_input_tokens
4. 1M beta + 支持的模型
5. 兜底 200K

## Token 计数：近似 vs 精确

| 策略 | 速度 | 用途 |
|------|------|------|
| **近似估算** | 毫秒级 | 热路径：shouldAutoCompact 每轮检查 |
| **精确计数** | API 调用 | 压缩前后对比、warning 判断 |

近似规则：
- 普通文本：length / 4
- JSON/JSONL：length / 2
- 图片/文档：固定 2000 tokens
- tool_use：序列化 name + input 后 / 4

3P Provider（OpenAI/Gemini 兼容层）无精确计数，退回到近似——影响自动压缩触发时机和阈值判断精度。

## 自动压缩触发阈值（200K 窗口示例）

| 阈值 | 约值 | 含义 |
|------|------|------|
| WARNING | ~167K | 闪烁警告，建议压缩 |
| AUTOCOMPACT | ~180K | 自动压缩触发 |
| BLOCKING | ~197K | 阻止新消息 |

关键常量：
- AUTOCOMPACT_BUFFER_TOKENS = 13,000
- WARNING/ERROR_THRESHOLD_BUFFER = 20,000
- MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES = 3（熔断）

逃逸条件：compact/session_memory 来源不触发、DISABLE_COMPACT、用户关闭 autoCompact、Context Collapse 模式、Reactive Compact 实验模式、连续失败上限。

## System Prompt 动态组装

System Prompt **不是写死的文本**，而是 string[] 数组，经三阶段管道发送给 API：

```text
getSystemPrompt()           → 组装内容（静态段 + 动态段）
buildEffectiveSystemPrompt() → 选择优先级路径
buildSystemPromptBlocks()    → 分块 + cache_control 标记
```

### 静态区 vs 动态区

| 区域 | 内容 | 缓存策略 |
|------|------|----------|
| **静态区** | Intro、Rules、Doing Tasks、Tools、Tone & Style | 可跨组织 global 缓存 |
| **BOUNDARY** | 分界标记（发送前移除，AI 看不到） | 分割静态/动态以实现 global cache |
| **动态区** | Session Guidance、Memory、Env、MCP、Scratchpad、Token Budget | 每次会话不同 |

### buildEffectiveSystemPrompt 五级优先级

| 优先级 | 条件 | 行为 |
|--------|------|------|
| 0. Override | overrideSystemPrompt 非空 | 完全替换 |
| 1. Coordinator | COORDINATOR_MODE + 环境变量 | 协调者专用提示词 |
| 2. Agent | mainThreadAgentDefinition 存在 | Proactive 追加；否则替换默认 |
| 3. Custom | --system-prompt 参数 | 替换默认 |
| 4. Default | 无特殊条件 | getSystemPrompt() 完整输出 |

appendSystemPrompt 始终追加到末尾（Override 除外）。

### Section 注册表

- **systemPromptSection**：计算一次，/clear 或 /compact 后重新计算（缓存友好）
- **DANGEROUS_uncachedSystemPromptSection**：每轮重新计算，破坏 Prompt Cache（仅用于 MCP 指令等真正动态内容）

### CLAUDE_CODE_SIMPLE 快速路径

环境变量 CLAUDE_CODE_SIMPLE=1 时，System Prompt 缩减为一行 CWD + Date，用于最小 token 测试。

## Prompt Cache 策略

Anthropic Prompt Cache 按 Blake2b 哈希复用前缀，任何字符变化导致缓存失效。

### 三种分块模式

**模式 1：MCP 工具存在**
- attribution → 不缓存
- prefix + rest → org 级缓存

**模式 2：Global Cache + Boundary（1P 专用）**
- static content → global 跨组织缓存
- dynamic content → 不缓存
- 最高缓存效率

**模式 3：默认（3P 或 Boundary 缺失）**
- prefix + rest → org 级缓存

Global Cache 条件：firstParty Provider + 未禁用 CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS。

## 三层压缩策略

| 层级 | 触发 | 是否需要 API |
|------|------|:------------:|
| **MicroCompact** | 单个工具输出过长 | 否 |
| **Session Memory Compact** | 自动压缩（feature flag） | 否 |
| **传统 API 摘要** | 手动 /compact 或 SM 不可用 | 是 |

### 压缩入口优先级

```text
/customInstructions 为空 ?
  → trySessionMemoryCompaction（优先）
Reactive-only 模式 ?
  → compactViaReactive
兜底 → microcompact + AI 模型生成摘要
```

### 第一层：MicroCompact

清除**旧工具输出内容**，不压缩整个对话。

可压缩工具：Read、Bash、Grep、Glob、WebSearch、WebFetch、Edit、Write

替换为 `[Old tool result content cleared]`。原始内容仍在 JSONL transcript，只是不再发给 API。有时间衰减：越旧越优先清除。

图片 block 超过 2000 token 估算也会被清除。

### 第二层：Session Memory Compact

tengu_session_memory + tengu_sm_compact 启用时，**直接用已提取的 Session Memory 作为摘要**，无需调用摘要模型。

保留窗口算法确保：
- 至少 10,000 token
- 至少 5 条含文本的消息
- 最多 40,000 token

**工具对完整性保护**：adjustIndexToPreserveAPIInvariants 确保每个 tool_result 有对应 tool_use，压缩切点不会破坏 API 不变量。

### 第三层：传统 API 摘要

SM 不可用时，调用 AI 生成对话摘要。

压缩前：stripImagesFromMessages、stripReinjectedAttachments

压缩后重新注入（POST_COMPACT_TOKEN_BUDGET = 50K）：
- 最近读取文件（最多 5 个，每文件 5K）
- 已激活技能（每技能 5K，总计 25K）
- CLAUDE.md
- MCP 工具发现结果

### CompactBoundary 边界标记

每次压缩后插入 SystemCompactBoundaryMessage：

```text
type: compact_boundary
compactMetadata:
  compactType: auto | manual | micro
  preCompactTokenCount
  lastUserMessageUuid
  preservedSegment: { summaryMessageUuid, preservedMessageUuids }
```

后续操作只处理**最后一条 boundary 之后**的消息。Compact 不删除历史——它追加 boundary，模型视图从 boundary 后开始。

## 项目记忆系统

纯文件存储，无数据库、无向量库。

### 目录布局

```text
~/.claude/projects/<sanitized-git-root>/memory/
├── MEMORY.md              入口索引（每次对话加载，200 行 / 25KB 上限）
├── user_role.md           用户记忆
├── feedback_testing.md    反馈记忆
├── project_*.md           项目记忆
├── reference_*.md         参考记忆
└── logs/YYYY/MM/YYYY-MM-DD.md   KAIROS 每日日志
```

同一 Git 仓库的所有 worktree 共享一个记忆目录。

### 四类型分类法

| 类型 | 存储内容 | 典型触发 |
|------|---------|---------|
| user | 用户角色、偏好、技术背景 | 「我是数据科学家」 |
| feedback | 对 AI 行为的纠正和确认 | 「别 mock 数据库」 |
| project | 非代码可推导的项目上下文 | 「合并冻结从周四开始」 |
| reference | 外部系统指针 | 「bugs 在 Linear INGEST 项目」 |

**只存储无法从当前项目状态推导的信息**。feedback 类型强调成功与失败双通道捕获，防止行为漂移。

### 智能召回

findRelevantMemories：用轻量 Sonnet 侧查询从清单中选出 ≤5 条最相关记忆。

- recentTools 去噪：跳过刚用过的工具文档，但保留警告/陷阱
- alreadySurfaced 去重：5 槽预算花在新的候选上

### 记忆漂移防御

Prompt 中「Before recommending from memory」section：记忆命名文件/函数/flag 是**写入时的 claim**，使用前需 grep/Read 验证仍存在。

### KAIROS 模式

长期 assistant 会话：AI 只往日期文件追加日志，/dream 技能夜间蒸馏为主题文件 + MEMORY.md 索引。

## 用户上下文 vs 系统上下文

| 类型 | 典型内容 | 注入位置 |
|------|---------|---------|
| userContext | 工作区、Coordinator 上下文、终端焦点状态 | 用户侧 context message |
| systemContext | 操作系统、终端信息、记忆 prompt | system prompt section |

Coordinator 模式下 getCoordinatorUserContext 注入 worker 可用工具列表、MCP 服务器、scratchpad 目录等信息。

## 上下文预处理在 Loop 中的位置

每轮 Agentic Loop 迭代**开始前**执行完整预处理管道（见 02 文档），与 compact 三层策略协同：

- MicroCompact 可能在 Loop 内每轮执行（推迟全量压缩）
- AutoCompact 在阈值触发时走 Session Memory 或 API 摘要
- Context Collapse（feature）提供另一种折叠/排水策略
- Reactive Compact 在 413 错误时即时压缩

**核心原则**：上下文管理是**动态的、每轮重新评估的**，不是会话开始时一次性固定。
