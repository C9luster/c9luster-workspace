# 03 — 上下文管理

Claude Code 的上下文工程是 Agent 能力的核心：如何在有限 token 窗口内维持「工作记忆」、项目知识和对话连续性。本章涵盖 System Prompt 组装、Token 预算、**多层上下文预算管道**、CLAUDE.md / memdir。

---

## 上下文窗口与有效空间

默认上下文窗口 200K tokens，但**实际可用于对话的空间远小于此**：

```text
上下文窗口（200K）
├── 系统提示词（~15-25K，缓存后成本低）
├── 工具定义（~10-20K，含 MCP）
├── 用户上下文（CLAUDE.md、git status 等）
├── 输出预留（maxOutputTokens）
│   ├── 默认上限：64K
│   ├── 实际默认：8K（slot-reservation 优化）
│   └── 触顶自动升级：一次 64K 重试
└── 剩余：对话历史空间（随对话增长）
```

**有效上下文** = 窗口大小 - min(maxOutputTokens, 20K)（压缩摘要需预留输出空间）。

### 窗口大小解析优先级

1. CLAUDE_CODE_MAX_CONTEXT_TOKENS 环境变量
2. 模型名含 [1m] 后缀 → 1M
3. 模型 capability 的 max_input_tokens
4. 1M beta + 支持的模型
5. 兜底 200K

## Token 计数：近似 vs 精确

| 策略 | 速度 | 用途 |
|------|------|------|
| **近似估算** | 毫秒级 | 热路径：shouldAutoCompact 每轮检查 |
| **精确计数** | API 调用 | 压缩前后对比、warning 判断 |

近似规则：
- 普通文本：length / 4
- JSON/JSONL：length / 2
- 图片/文档：固定 2000 tokens
- tool_use：序列化 name + input 后 / 4

3P Provider（OpenAI/Gemini 兼容层）无精确计数，退回到近似——影响自动压缩触发时机和阈值判断精度。

## 自动压缩触发阈值（示例）

以 ~200K 有效窗口、默认 buffer 13K 为例：AUTOCOMPACT 约在窗口减去 buffer 处触发；WARNING/BLOCKING 另加 ~20K 缓冲概念。大窗口（400K/800K+）buffer 升至 30K/50K，**不要再写死「一律 13K」**。

关键常量（见 `autoCompact.ts`）：
- `AUTOCOMPACT_BUFFER_TOKENS = 13_000`（默认档）
- `getAutocompactBufferTokens(model)` 动态上调
- `WARNING/ERROR_THRESHOLD_BUFFER ≈ 20_000`
- `MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES = 3`

## System Prompt 动态组装

System Prompt **不是写死的文本**，而是 string[] 数组，经三阶段管道发送给 API：

```text
getSystemPrompt()           → 组装内容（静态段 + 动态段）
buildEffectiveSystemPrompt() → 选择优先级路径
buildSystemPromptBlocks()    → 分块 + cache_control 标记
```

### 静态区 vs 动态区

| 区域 | 内容 | 缓存策略 |
|------|------|----------|
| **静态区** | Intro、Rules、Doing Tasks、Tools、Tone & Style | 可跨组织 global 缓存 |
| **BOUNDARY** | 分界标记（发送前移除，AI 看不到） | 分割静态/动态以实现 global cache |
| **动态区** | Session Guidance、Memory、Env、MCP、Scratchpad、Token Budget | 每次会话不同 |

### buildEffectiveSystemPrompt 五级优先级

| 优先级 | 条件 | 行为 |
|--------|------|------|
| 0. Override | overrideSystemPrompt 非空 | 完全替换 |
| 1. Coordinator | COORDINATOR_MODE + 环境变量 | 协调者专用提示词 |
| 2. Agent | mainThreadAgentDefinition 存在 | Proactive 追加；否则替换默认 |
| 3. Custom | --system-prompt 参数 | 替换默认 |
| 4. Default | 无特殊条件 | getSystemPrompt() 完整输出 |

appendSystemPrompt 始终追加到末尾（Override 除外）。

### Section 注册表

- **systemPromptSection**：计算一次，/clear 或 /compact 后重新计算（缓存友好）
- **DANGEROUS_uncachedSystemPromptSection**：每轮重新计算，破坏 Prompt Cache（仅用于 MCP 指令等真正动态内容）

### CLAUDE_CODE_SIMPLE 快速路径

环境变量 CLAUDE_CODE_SIMPLE=1 时，System Prompt 缩减为一行 CWD + Date，用于最小 token 测试。

---

## Prompt Cache 策略

Anthropic Prompt Cache 按 Blake2b 哈希复用前缀，任何字符变化导致缓存失效。

### 三种分块模式

**模式 1：MCP 工具存在**
- attribution → 不缓存
- prefix + rest → org 级缓存

**模式 2：Global Cache + Boundary（1P 专用）**
- static content → global 跨组织缓存
- dynamic content → 不缓存
- 最高缓存效率

**模式 3：默认（3P 或 Boundary 缺失）**
- prefix + rest → org 级缓存

Global Cache 条件：firstParty Provider + 未禁用 CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS。

## 三层压缩策略 → 多层上下文预算管道

旧文档写「三层压缩」已过粗。当前 `queryLoop` 每轮迭代前实际是一条**多层管道**，再叠加 autocompact 内部的 SM / API 两阶段：

| 层级 | 触发 / 作用 | 是否需要摘要 API | 源码 |
|------|-------------|------------------|------|
| **Tool Result Budget** | 大工具结果内容替换进预算 | 否 | `toolResultStorage.ts` |
| **Snip** | HISTORY_SNIP：按策略裁历史；`snip_boundary` | 否 | `snipCompact.ts` |
| **Microcompact** | 清除旧工具输出正文 | 否 | `microCompact.ts` |
| **Cached Microcompact** | cache editing 分支 | 否 | `cachedMicrocompact.ts` |
| **Context Collapse** | feature 门控；部分开源还原实现中为 stub | 否 | `contextCollapse/index.ts` |
| **Session Memory Compact** | autocompact 优先路径 | 否 | `sessionMemoryCompact.ts` |
| **API 摘要 Compact** | SM 不可用或手动 /compact | 是 | `compact.ts` |
| **Reactive Compact** | prompt-too-long 恢复 | 是 | `reactiveCompact.ts` |

**投影语义**：磁盘 JSONL 尽量保留；发给模型的是投影视图。`compact_boundary` 与 `snip_boundary` 都是「模型从边界后看历史」，但写入与恢复语义不同（见 08）。

### Autocompact 阈值与动态 buffer

```text
阈值 ≈ effectiveContextWindow - getAutocompactBufferTokens(model)
```

| 有效窗口 | buffer |
|----------|--------|
| ≥ 800K | 50,000 |
| ≥ 400K | 30,000 |
| 默认 | 13,000（`AUTOCOMPACT_BUFFER_TOKENS`） |

另有 WARNING/ERROR buffer（约 20K）、连续失败熔断（`MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES = 3`）、`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` 测试覆盖。

逃逸条件仍包括：compact/session_memory 来源、DISABLE_COMPACT、用户关 autoCompact、Reactive-only 实验路径、连续失败上限等。

### 压缩入口优先级（autocompact / 手动）

```text
可走 Session Memory？
  → trySessionMemoryCompaction（优先，无摘要 API）
Reactive-only 模式？
  → compactViaReactive
兜底 → microcompact 清理 + API 模型生成摘要
```

### MicroCompact（仍关键）

清除**旧工具输出内容**，不整段扔掉对话。常见可清工具：Read、Bash、Grep、Glob、WebSearch、WebFetch、Edit、Write 等。替换为占位句；原始仍可在 transcript。旧结果优先清；大图 block 也可清。

### Session Memory Compact

tengu_session_memory + tengu_sm_compact：用已提取 Session Memory 当摘要。保留窗口算法（至少约 10K token / 至少 5 条含文本消息 / 上限约 40K）+ `adjustIndexToPreserveAPIInvariants` 保护 tool_use/tool_result 成对。

### API 摘要 Compact

SM 不可用时调用模型摘要。压缩前可 strip 图片/附件；压缩后按 POST_COMPACT 预算 reinject 最近文件、技能等。

### Context Collapse  caveat

`src/services/contextCollapse/index.ts` 在部分开源还原树中是 **auto-generated stub**（空实现）。文档与恢复路径里仍保留 collapse 相关类型/continue reason，但**不要默认假设生产环境已启用真实折叠**。

## 长期记忆分层

跨会话、跨压缩仍可能影响行为的「记忆」分几层（与当轮 transcript 工作记忆区分）：

| 层级 | 机制 | 性质 |
|------|------|------|
| **显式指令** | `CLAUDE.md` 链（Managed → User → Project → Local） | 人写/可提交；启动与 compact 后工程重载 |
| **自动沉淀** | memdir：`MEMORY.md` 索引 + user/feedback/project/reference 文件 | 默认开启（可关）；按需召回，非整库灌入 |
| **会话连续性** | JSONL transcript + compact/snip 投影 | 同会话；压缩后靠摘要与 reinject |
| **工艺知识** | Skills（见 [07](./07-扩展机制.md)） | 触发时 inline 正文，非常驻全文 |

细节见下文「项目记忆：CLAUDE.md 与 memdir」。

## 项目记忆：CLAUDE.md 与 memdir

| 机制 | 说明 |
|------|------|
| **CLAUDE.md** | 项目/用户指令；嵌套路径可按加载记录进 `loadedNestedMemoryPaths` |
| **memdir / MEMORY.md** | Auto memory entrypoint（`src/memdir/`）；可配合 `LocalMemoryRecallTool` |
| **TEAMMEM** | 团队组合记忆 feature |
| **KAIROS / dream** | 长期助手日志与回顾类能力（见 09） |

### CompactBoundary 边界标记

每次压缩后可插入 SystemCompactBoundaryMessage：

```text
type: compact_boundary
compactMetadata:
  compactType: auto | manual | micro
  preCompactTokenCount
  lastUserMessageUuid
  preservedSegment: { summaryMessageUuid, preservedMessageUuids }
```

后续模型视图通常只处理**最后一条 boundary 之后**的消息。Compact/Snip 不靠「删掉 JSONL」——更多是追加边界 + 投影。

## 项目记忆系统（memdir 细节）

纯文件存储，无数据库、无向量库。

### 目录布局

```text
~/.claude/projects/<sanitized-git-root>/memory/
├── MEMORY.md              入口索引（每次对话加载，200 行 / 25KB 上限）
├── user_role.md           用户记忆
├── feedback_testing.md    反馈记忆
├── project_*.md           项目记忆
├── reference_*.md         参考记忆
└── logs/YYYY/MM/YYYY-MM-DD.md   KAIROS 每日日志
```

同一 Git 仓库的所有 worktree 共享一个记忆目录。

### 四类型分类法

| 类型 | 存储内容 | 典型触发 |
|------|---------|---------|
| user | 用户角色、偏好、技术背景 | 「我是数据科学家」 |
| feedback | 对 AI 行为的纠正和确认 | 「别 mock 数据库」 |
| project | 非代码可推导的项目上下文 | 「合并冻结从周四开始」 |
| reference | 外部系统指针 | 「bugs 在 Linear INGEST 项目」 |

**只存储无法从当前项目状态推导的信息**。feedback 强调成功与失败双通道，防止行为漂移。

### 智能召回

findRelevantMemories：轻量侧查询选出 ≤5 条相关记忆；recentTools 去噪、alreadySurfaced 去重。

### 记忆漂移防御

记忆里的文件/函数/flag 是写入时 claim，使用前应 grep/Read 验证仍存在。

### KAIROS 模式

长期 assistant：往日期文件追加日志；/dream 等技能可蒸馏主题文件 + MEMORY.md 索引。

## 用户上下文 vs 系统上下文

| 类型 | 典型内容 | 注入位置 |
|------|---------|---------|
| userContext | 工作区、Coordinator 上下文、终端焦点状态 | 用户侧 context message |
| systemContext | 操作系统、终端信息、记忆 prompt | system prompt section |

Coordinator 模式下 `getCoordinatorUserContext` 注入 worker 工具列表、MCP、scratchpad 等。

## 上下文预处理在 Loop 中的位置

每轮 Agentic Loop 迭代**开始前**执行完整预处理管道（见 02），与本章多层预算管道一致：

- Tool Result Budget / Snip / Microcompact 可每轮执行
- Autocompact 阈值触发时走 Session Memory 或 API 摘要
- Context Collapse 在部分实现中为 stub；continue 路径仍可能保留
- Reactive Compact 在 413 时即时压缩

**核心原则**：上下文管理是**动态的、每轮重新评估的**，不是会话开始时一次性固定。
