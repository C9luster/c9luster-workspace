# 01 — 概述与架构

## 一句话定义

Claude Code 是一个**运行在本地终端中的 Agentic Coding System**。它不是给建议的聊天机器人——它直接在你的项目目录中读代码、改文件、跑命令、调试程序，拥有完整的 Shell 能力。

## 技术定位：三个关键词

| 关键词 | 含义 |
|--------|------|
| **Terminal-native** | 原生 CLI 应用，不是 IDE 插件、不是 Web 界面、不是 API wrapper |
| **Agentic** | AI 自主决策工具调用链，不是「一问一答」的聊天模式 |
| **Coding system** | 面向软件工程全流程，不是通用问答工具 |

## 与同类工具的架构差异

| 工具 | 架构模式 | 运行位置 | 工具执行 |
|------|----------|----------|----------|
| **Claude Code** | Terminal-native agentic loop | 本地进程 | 直接 Shell 执行 |
| Cursor / Copilot | IDE-integrated autocomplete + chat | IDE 进程内 | LSP / IDE API |
| Aider | CLI chat → git patch | 本地进程 | 文件操作为主 |
| ChatGPT / Claude.ai | Cloud chat + artifacts | 浏览器/云端 | 沙箱容器 |

核心差异：Claude Code 拥有**完整的 Shell 访问权**——可以做任何你在终端里能做的事，因此需要对应的权限模型与安全机制来约束。

## 它不是什么

- **不是 IDE 插件**：没有图形界面，不依赖 VS Code
- **不是 API wrapper**：有自己的工具系统、权限模型、上下文工程、会话管理
- **不是聊天机器人**：输出是实际的文件修改、命令执行
- **不是无脑执行器**：每个敏感操作都有权限检查和用户确认

## 五层架构

Claude Code 从上到下分为五个层次，职责清晰、边界分明：

| 层次 | 职责 | 关键词 |
|------|------|--------|
| **交互层** | 终端 UI、用户输入、消息展示 | React/Ink、PromptInput、REPL |
| **编排层** | 多轮对话、会话持久化、成本追踪 | QueryEngine、transcript |
| **核心循环层** | 单轮：发请求 → 收响应 → 执行工具 → 循环 | Agentic Loop、State |
| **工具层** | AI 的「双手」——读写文件、执行命令 | Tool 接口、MCP |
| **通信层** | 与 Claude API 的流式通信 | Streaming、多 Provider |

### 端到端数据流

一次典型用户请求（例如「修复 TypeScript 报错」）的完整路径：

```text
1. 入口层
   CLI 启动 → Commander 解析参数 → 初始化认证/遥测/策略 → 加载工具 → 启动 REPL 或管道模式

2. 交互层
   PromptInput 捕获输入 → processUserInput 处理斜杠命令/附件 → UserMessage 加入会话

3. 编排层（QueryEngine）
   管理 turn 生命周期、token 预算、compaction 触发、transcript 持久化、文件历史快照

4. 核心循环（query / queryLoop）
   组装上下文 → 调 API → 收流式响应 → 解析 tool_use → 权限检查 → 执行工具 → 结果回传 → 循环

5. 工具执行
   Bash / Read / Edit / Agent / Skill 等实际执行

6. 通信层
   流式 HTTP，支持 Anthropic Direct、Bedrock、Vertex、Foundry、OpenAI/Gemini/Grok 兼容层
```

### 典型 Agentic Loop 示例

| Turn | AI 决策 | 工具调用 | 结果 |
|------|---------|----------|------|
| 1 | 先看报错 | Bash 运行 dev 并捕获 stderr | TypeScript 错误输出 |
| 2 | 定位文件 | Read 读取源文件 | 源代码内容 |
| 3 | 搜索类型 | Grep 搜索 interface | 类型定义位置 |
| 4 | 修复 | Edit 修改代码 | 代码已修改 |
| 5 | 验证 | Bash 再次运行 dev | 编译通过 |

每一步都是 AI 自主决策——决定用哪个工具、传什么参数、何时停止。

## 四种核心设计原则

### 1. 流式优先（Streaming-first）

- 所有 API 通信都是流式的，用户看到 AI「逐字打出」
- StreamingToolExecutor 在流式过程中就开始并行执行工具
- 模型降级时，已收集的消息被标记 tombstone 并清空，重试整个流式请求

### 2. 工具即能力（Tool as Capability）

- 每个工具是结构化类型，通过工厂创建
- 工具列表在每次 API 调用时动态组装（非全局缓存），因为 isEnabled 可能随运行时变化
- MCP 工具通过 mcpInfo 标记来源，支持 server 级别 blanket deny

### 3. 权限即边界（Permission as Boundary）

- 每次工具调用：validateInput → checkPermissions 双重检查
- 规则从 8 个来源汇聚（session → project → user → managed → default 等）
- Plan Mode 通过 prepareContextForPlanMode 切换为只读，退出时自动恢复

### 4. 上下文即记忆（Context as Memory）

- System Prompt 动态组装：CLAUDE.md、git 状态、日期、MCP 列表
- Auto-compact 每轮迭代前评估 token 阈值
- 压缩摘要通过 buildPostCompactMessages 替换原始消息

## 三种交互形态

Claude Code 支持三种不同的「接入/交互」维度，常被混淆：

| 维度 | 是什么 | 使用方式 | 典型场景 |
|------|--------|----------|----------|
| **REPL** | 终端交互形态 | 直接运行 claude 命令，React Ink 渲染 TUI | 开发者日常编码、复杂多步任务 |
| **SDK** | 程序化接入方式 | 安装 SDK 包，通过 API 发送查询 | CI/CD、自动化脚本、应用集成 |
| **ACP** | 通信协议标准 | 通过 ACP 适配器连接第三方编辑器 | JetBrains IDE、Zed 等编辑器集成 |

- **REPL 模式**：onQueryImpl 直接调用 query()，完整工具链与 UI
- **SDK/ACP 模式**：QueryEngine 管理会话，submitMessage 逐步 yield SDKMessage

### 管道模式（Headless）

```bash
echo "say hello" | claude -p
```

支持非交互式管道输入，适合自动化与 CI 集成。Headless 路径在 coordinator 工具过滤、system prompt 组装等方面与交互 REPL 存在边界差异，需单独验证。

---

## 为什么选择终端

- **完整 Shell 访问**：可运行任何命令行工具，无需为每个能力写插件
- **项目原生**：直接在项目目录工作，理解文件系统、git 状态
- **可组合性**：管道模式可嵌入 CI/CD
- **低延迟**：React/Ink TUI，无 Electron 开销

代价：用户需适应命令行界面；也因此吸引需要**真正掌控开发环境**的开发者。

## API Provider 支持

| Provider | 说明 |
|----------|------|
| firstParty | Anthropic 官方 API 直连（默认） |
| bedrock | AWS Bedrock |
| vertex | Google Vertex AI |
| foundry | Anthropic Foundry 内部部署 |
| openai | OpenAI 兼容层（Ollama/DeepSeek/vLLM） |
| gemini | Google Gemini 兼容层 |
| grok | xAI Grok 兼容层 |

Provider 影响：可用 beta headers、Prompt Cache 策略（global scope 仅 1P）、Token 计数精度（OpenAI/Gemini 兼容层退回到近似估算）。
