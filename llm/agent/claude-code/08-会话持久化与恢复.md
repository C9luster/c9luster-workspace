# 08 — 会话持久化与恢复

Claude Code 的本地会话核心是 **append-only JSONL Transcript**。理解持久化是理解 Agent 跨 turn、跨进程、跨 compact 行为的关键。

---

## 核心不变量

| 不变量 | 含义 |
|--------|------|
| JSONL 尽量 append-only | compact、branch、sidechain 优先追加，不改旧历史 |
| uuid/parentUuid 决定世界线 | 文件顺序≠恢复顺序，靠链路回溯 |
| metadata 不参与主链 | title、mode、worktree 等通过 sessionId 合并 |
| compact 不删除历史 | 追加 boundary，模型视图从 boundary 后开始 |
| subagent 是 sidechain | 完整对话在独立 JSONL，父会话只见结果/通知 |
| remote agent 不是 sidechain | 本地 sidecar 身份，执行状态来自 CCR |

---

## 系统分层

```text
磁盘层（append-only JSONL + sidecar metadata）
  → 链路层（uuid / parentUuid / leaf）
  → 投影层（compact / snip / tool_result budget / context-collapse）
  → 恢复层（deserialize / interrupt detection / metadata restore）
  → 运行层（REPL / QueryEngine / AgentTask / RemoteTask）
```

## Entry 数据模型

### 三大类 Entry

| 类别 | 典型 type | 进入 parentUuid 链 | 用途 |
|------|-----------|:------------------:|------|
| transcript message | user, assistant, attachment, system | 是 | 对话链、模型上下文 |
| session metadata | custom-title, tag, mode, worktree-state, agent-setting | 否 | 恢复模式、标题、worktree |
| message metadata | file-history-snapshot, summary | 否 | 文件历史、归因 |

### TranscriptMessage 关键字段

| 字段 | 含义 |
|------|------|
| uuid | 消息 ID |
| parentUuid | 链路父节点 |
| logicalParentUuid | compact 断链场景逻辑父 |
| isSidechain | 是否 subagent sidechain |
| agentId | sidechain 所属 agent |
| teamName/agentName | swarm 展示元数据 |

## 写入机制

recordTranscript → enqueueWrite → 定时批量 drainWriteQueue → appendToFile

- 按文件分组写队列，防并发覆盖
- 读取上限 50MB（防 OOM）
- 可选远程持久化（CCR v2 / Ingress）

---

## 恢复链路（--resume）

```text
1. 解析 resume 参数（UUID / .jsonl 路径 / 最近会话 picker）
2. loadTranscriptFromFile → 重建 Message[]
3. 恢复 costState、agentSetting、mode、worktree
4. 可选 --rewind-files 恢复文件快照
5. QueryEngine({ initialMessages }) 继续对话
```

### 链路重建算法

1. transcript message → uuid map
2. metadata → 各自 map
3. 选择最新 leaf
4. 从 leaf 沿 parentUuid 回溯
5. 应用 compact、snip、preserved segment、content replacement 投影
6. 恢复内存状态

---

## 上下文视图 vs 磁盘历史

**磁盘上有 ≠ 模型能看到。**

| 机制 | 磁盘 | 模型视图 |
|------|------|----------|
| Compact boundary | 保留全部历史 | 仅 boundary 后 + 摘要 |
| MicroCompact | 原始 tool_result 仍在 JSONL | 内容替换为 cleared 标记 |
| Snip | 历史仍在 | 摘要化旧段 |
| content-replacement | 完整结果在 sidecar | 消息中引用或截断 |

getMessagesAfterCompactBoundary 决定 API 发送范围。

---

## Subagent Sidechain

```text
主 session JSONL:
  assistant: tool_use Agent(...)
  user: tool_result（sync）或 无（async，靠 notification）

sidechain JSONL:
  完整子 Agent 对话（user/assistant/tool 循环）
  .meta.json: agentType, worktreePath, description
```

恢复：resumeAgentBackground 从 sidechain 续跑；SendMessage(to: agentId) 对 stopped agent 尝试 sidechain resume。

Fork agent 恢复需 metadata agentType:"fork" 正确。

| 操作 | 作用 |
|------|------|
| /branch | transcript 分支，新 parentUuid 链 |
| --fork-session | 启动时 fork 会话 |
| /fork | 命令级 fork |
| AgentTool fork | 继承父上下文的后台 agent |

## 错误恢复矩阵

| 场景 | 恢复策略 |
|------|----------|
| 用户 ESC 中断 | 合成 tool_result，aborted 状态 |
| prompt-too-long | collapse drain → reactive compact → 失败则 PTL 错误 |
| max_output_tokens | escalate 64K → recovery 消息 ×3 |
| 模型 fallback | tombstone + 切换模型重试 |
| 进程崩溃 | --resume 从 JSONL 重建；in-process teammate **不能**完整恢复 |
| remote 404/archive | 删除 sidecar，需重建 remote agent |
| compact 连续失败 3 次 | 熔断，停止 auto compact |

### 中断检测

conversationRecovery 检测未完成 tool_use、orphaned permission 等异常状态，resume 时提示或修复。

## Session Mode 持久化

Coordinator mode 写入主 JSONL：

```json
{"type":"mode","sessionId":"...","mode":"coordinator"}
```

matchSessionMode 对齐环境变量，防止 normal 环境恢复 coordinator 会话。

## 文件历史快照

file-history-snapshot entry 绑定 messageId。--rewind-files \<user-message-id\> 恢复该时间点所有被修改文件——独立于 git。

## UI 投影 vs 真相

| UI 组件 | 数据源 | 不能说明 |
|---------|--------|----------|
| TaskListV2 | task files + teamContext | owner teammate 一定活跃 |
| TeammateSpinnerTree | in-process teammates | pane teammate 全状态 |
| BackgroundAgentSelector | backgrounded LocalAgentTask | remote/teammate |
| TeamsDialog | teamContext + TeamFile | runner 一定可恢复 |

调试：**文件还在吗 → AppState 投影还在吗 → runtime task running 吗 → 通道可用吗 → sidechain/inbox 够吗**

---

## 持久化设计原则

1. **Append-only 优先**：审计友好，恢复可回溯
2. **链路与投影分离**：uuid 链是真相，compact 是视图变换
3. **Sidechain 隔离**：子 Agent 不污染主 transcript token
4. **Metadata 旁路**：模式/worktree/成本不与消息链纠缠
5. **Best-effort 恢复**：team/teammate/pane 状态不保证跨进程完整
