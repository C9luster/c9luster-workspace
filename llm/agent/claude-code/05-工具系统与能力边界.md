# 05 — 工具系统与能力边界

工具是 AI 的「双手」——模型只能生成文本，Tool 系统替它读文件、跑命令、派 Agent、调用 MCP。

---

## Tool 抽象：40+ 字段的统一接口

所有工具实现结构化 Tool 类型（非 class），定义在 `src/Tool.ts`（约 **43** 个字段/方法量级）。核心四要素：

| 字段 | 说明 |
|------|------|
| name | 唯一标识（Read、Bash、Agent 等） |
| description(input) | **动态描述**，随输入变化 |
| inputSchema | Zod schema 参数校验 |
| call() | 执行函数，返回 ToolResult |

### 生命周期方法链

```text
validateInput() → canUseTool()（UI）→ checkPermissions() → call() → ToolResult
```

### 其他重要字段

| 类别 | 字段 | 说明 |
|------|------|------|
| 注册 | aliases, searchHint, **shouldDefer**, **alwaysLoad**, isEnabled | 发现与延迟加载 |
| 安全 | isReadOnly, isDestructive, **isConcurrencySafe**, interruptBehavior | 权限与并发（并行闸门） |
| 输出 | maxResultSizeChars, mapToolResultToToolResultBlockParam | 通常 100K 上限 |
| 上下文 | prompt(), getPath(), **backfillObservableInput**, extractSearchText | prompt cache / 权限 / 搜索 |

实现主体已迁到 **`packages/builtin-tools/`**，由 `src/tools.ts` 的 `getAllBaseTools()` 组装。

## 工具注册与过滤

`getAllBaseTools()` 组装 50+ 候选；`getTools(permissionContext)` 再过滤后传给 API（**每次组装，非全局缓存**）。

### 常见常驻工具

Agent、TaskOutput、Bash、Read/Edit/Write、NotebookEdit、**Artifact**、WebFetch、WebSearch、TodoWrite、AskUserQuestion、Skill、EnterPlanMode、ExitPlanModeV2、TaskStop、Brief、ListMcpResources、ReadMcpResource、**Execute**（调用 deferred 工具）等。

### 条件工具（节选，以 `getAllBaseTools` 为准）

| 条件 | 工具 |
|------|------|
| 无 embedded search（`hasEmbeddedSearchTools()`） | Glob、Grep |
| `isTodoV2Enabled()` | TaskCreate / Get / Update / List（SDK 常需 `CLAUDE_CODE_ENABLE_TASKS=1`） |
| Worktree 模式 | EnterWorktree / ExitWorktree |
| Agent Swarms 默认开 | TeamCreate / Delete、SendMessage、ListPeers… |
| SearchExtraTools 乐观开启 | **SearchExtraTools** + 始终注册的 **Execute** |
| HISTORY_SNIP | SnipTool |
| WORKFLOW_SCRIPTS | WorkflowTool |
| KAIROS / proactive 族 | Sleep、Cron*、RemoteTrigger、Monitor、PushNotification… |
| WEB_BROWSER_TOOL | WebBrowser |
| ant-only | REPL、Config、Tungsten、SuggestBackgroundPR… |
| `CLAUDE_CODE_SIMPLE=1` | 仅 Bash/Read/Edit（+ coordinator 时少量编排工具）；REPL 模式可只露 REPL |

### Deferred 工具加载（重要演进）

```text
SearchExtraTools → 发现被 shouldDefer 的工具
Execute → 真正调用 deferred 工具
```

turn-1 不必把全部 schema 塞进上下文；`alwaysLoad` 可强制常驻。这是工具面膨胀时的关键 Agent 设计。

## 工具执行模式

### 串行 vs 并行

- **StreamingToolExecutor**：流式过程中按 `isConcurrencySafe(input)` 决定能否与已在跑的工具重叠；不安全则排队独占
- **runTools**：`partitionToolCalls` — 连续 safe 批并发，unsafe 批串行
- Bash 失败可 abort sibling；streaming fallback 调用 `discard()`

详见 [02](./02-交互形态与Agentic-Loop.md)。

### Bash 工具特性

- 流式 onProgress 逐行推送
- tree-sitter bash AST 解析（命令模式权限匹配）
- 长时间命令自动后台化
- readOnlyValidation 判定只读命令

### 文件工具

Read / Edit / Write：getPath 用于权限 glob；Edit 前 `fileHistoryMakeSnapshot`。

### Artifact

支持制品上传/展示（含 Markdown、高亮、mermaid 等演进）；与纯 Edit 文件路径互补。

## Tool vs Skill

| | Tool | Skill |
|---|---|---|
| 粒度 | 单个原子操作 | 完整工作流 |
| 触发 | AI 自主选择 | 用户 /skill 或 SkillTool 匹配 |
| 本质 | TypeScript 执行逻辑 | **Prompt + 权限配置** |
| 执行 | call() | inline 注入 UserMessage 或 fork 子 Agent |

Skill 洞见：**复杂任务的关键在 Prompt 质量**，不是审查引擎代码。

## MCP 集成

### 架构链路

```text
配置合并（settings / .mcp.json / 插件 / 企业 / 内置）
  → connectToServer（memoize 缓存）
  → fetchToolsForClient（LRU 20）
  → 包装为 MCPTool（统一 Tool 接口）
  → assembleToolPool
  → 工具名: mcp__<server>__<tool>
```

### 内置 vs 外部 MCP

| | 内置 | 外部 |
|---|---|---|
| 示例 | computer-use, claude-in-chrome, vscode-sdk | 用户配置的 stdio/SSE/HTTP |
| 传输 | InProcessTransport（同进程零开销） | StdioClientTransport 或网络 |
| 配置 | dynamic scope，启动时注册 | settings.json / .mcp.json |

### MCP 工具权限

- getToolNameForPermissionCheck 支持 mcp__server 级别 blanket deny
- MCP Skills 的 Prompt **禁止内联 shell**（远程内容不可信）

## Task 管理（V2）

### Work Item Task

| 字段 | 说明 |
|------|------|
| id, subject, description | 任务内容 |
| owner | 认领者（teammate name） |
| status | pending / in_progress / completed |
| blocks, blockedBy | 依赖关系 |

存储：~/.claude/tasks/\<taskListId\>/\<id\>.json

Swarm 下 TaskUpdate 增强：
- in_progress 且 owner 空 → 自动设 owner
- owner 变化 → 写 task_assignment 到 mailbox
- completed → TaskCompleted hooks + 提示 TaskList 找下一项

### Runtime Task 类型

| 类型 | 场景 |
|------|------|
| LocalAgentTask | 普通后台 agent、fork、coordinator worker |
| InProcessTeammateTask | in-process teammate |
| RemoteAgentTask | remote agent |
| LocalShellTask | 后台 shell |
| LocalWorkflowTask | workflow 编排 |
| DreamTask | memory dream |
| MonitorMcpTask | MCP 监控 |

## ToolSearch（按需加载）

feature 启用时，部分工具 shouldDefer=true，模型通过 ToolSearch 关键词匹配按需加载，减少每 turn 工具定义 token 占用。SkillTool 等 alwaysLoad 永不被延迟。

---

## Coordinator 工具池差异

| 角色 | 工具 |
|------|------|
| Coordinator 主线程 | Agent、SendMessage、TaskStop、SyntheticOutput、PR 订阅类 MCP |
| worker | ASYNC_AGENT_ALLOWED_TOOLS（排除 TeamCreate、SendMessage 等） |
| simple mode worker | 仅 Bash、Read、Edit |

worker 工具池由 AgentTool 独立组装，不继承主线程过滤结果。
