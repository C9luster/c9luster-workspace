# 05 — 工具系统与能力边界

## 装配入口

工具列表由 `backend/packages/harness/deerflow/tools/tools.py` 中的 `get_available_tools(...)` 组装，并在 Lead Agent 工厂中经授权过滤后交给 `create_agent`。

装配顺序（逻辑上）：

```text
配置加载的工具 + 内置工具 + MCP 工具 + ACP 工具
  → 去重（同名工具会导致模型选择歧义）
  → authz / 通道策略过滤
  → 交给 create_agent
```

## 内置工具面

`BUILTIN_TOOLS` 常驻集合包括：

| 工具 | 作用 |
|------|------|
| `present_file` | 向用户呈现产物文件 |
| `ask_clarification` | 人机澄清 |
| `review_skill_package` | 技能包审查 |

按配置与运行时条件追加：

| 条件 | 追加工具 |
|------|----------|
| 后台任务能力可用 | `list_background_tasks`、`cancel_background_task` |
| 上传能力开启 | `list_uploaded_files` |
| 技能管理开启 | `skill_manage` |
| 子 Agent 开启 | `task`（`SUBAGENT_TOOLS`） |
| 批处理运行时可用 | `batch_task`、`batch_status`、`cancel_batch`、`read_batch_item` |
| 视觉能力开启 | `view_image` |
| ACP 配置存在 | `invoke_acp_agent` 等 |

沙箱侧 bash / 读写 / 浏览等通常来自配置的 tool group（如 `bash`），经 sandbox security 与 host-bash 策略决定是否允许落在宿主机执行。

## Sandbox 与工具边界

- 工具执行默认绑定 Thread 级 sandbox（由 `SandboxMiddleware` 在 `before_agent` 获取、`after_agent` 释放）
- Provider 由 `sandbox.use` 指定，可以是本机目录映射、Docker、已接入的云端实现，或自定义 `SandboxProvider`
- Host bash 受 `allow_host_bash` 约束；打开后本机 Provider 不再构成文件系统安全边界
- 沙箱提供进程与文件系统隔离，不替代语义层授权（见 [06](./06-安全权限与Plan-Mode.md)）

## MCP

- MCP 客户端位于 `backend/packages/harness/deerflow/mcp/`
- 远端工具经桥接进入同一工具列表，并由 `tag_mcp_tool` 等打上元数据
- MCP task runtime 可用时，可与后台任务能力协同

## Skills 相关工具

- 技能说明进入上下文（见 [03](./03-上下文管理.md)）
- `skill_manage` / `review_skill_package` 负责管理与审查
- 技能内容路径经 security scanner（`skills/security_scanner.py`）；图内扫描调用须 `attach_tracing=False`

## ACP

在配置启用时，可通过 `build_invoke_acp_agent_tool` 将外部 ACP Agent 作为可调用工具面接入。

## 能力边界摘要

| 边界 | 机制 |
|------|------|
| 可见工具集 | 配置开关 + authz + 通道策略 |
| 执行隔离 | Sandbox Provider |
| 语义授权 | GuardrailMiddleware + GuardrailProvider |
| 人机门控 | `ask_clarification` + ClarificationMiddleware |
| 子任务隔离 | `task` / Subagent（更小 middleware 与工具面） |
