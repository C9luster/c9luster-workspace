# 07 — 扩展机制

DeerFlow 的可扩展性围绕四条主线：**Middleware**、**Plugins / Extensions**、**Skills**、**MCP**。其中 Middleware 承担生命周期拦截职责，是本脚手架的 Hook 等价层。

---

## Middleware（Hook 等价层）

> 本节只描述 DeerFlow 自身的 middleware 机制。

LangChain `create_agent` 提供固定槽位；DeerFlow 在这些槽位上挂载有序中间件链：

| 槽位 | 执行方向 | 典型用途 |
|------|----------|----------|
| `before_agent` | 正序 0→N | 线程目录、上传扫描、获取沙箱 |
| `before_model` | 正序 | 摘要、待办注入等 |
| `after_model` | 反序 N→0 | 循环检测、子 Agent 限额、标题 |
| `after_agent` | 反序 | 记忆入队、释放沙箱 |
| `wrap_model_call` | 外→内 | 补悬空 ToolMessage、看图、loop warning |
| `wrap_tool_call` | 外→内 | Guardrail、工具错误处理、clarification |

完整默认链与 Lead / Subagent 差异见上游 `backend/docs/middleware-execution-flow.md`。

### 默认 Lead 链（摘要）

| # | Middleware | 主要槽位 |
|---|------------|----------|
| 0 | ThreadDataMiddleware | before_agent |
| 1 | UploadsMiddleware | before_agent |
| 2 | SandboxMiddleware | before_agent / after_agent |
| 3 | DanglingToolCallMiddleware | wrap_model_call |
| 4 | GuardrailMiddleware | wrap_tool_call |
| 5 | ToolErrorHandlingMiddleware | wrap_tool_call |
| 6 | SummarizationMiddleware | before_model |
| 7 | TodoMiddleware | before_model / after_model / wrap_model_call |
| 8 | TitleMiddleware | after_model |
| 9 | MemoryMiddleware | after_agent |
| 10 | ViewImageMiddleware | wrap_model_call |
| 11 | SubagentLimitMiddleware | after_model |
| 12 | LoopDetectionMiddleware | 多槽位 |
| 13 | ClarificationMiddleware | wrap_tool_call（靠后） |

Subagent 复用运行时段，并带上技能激活与策略、悬空工具调用修补、循环检测、令牌预算和安全结束原因。压缩开启时还有 DurableContext 与 Summarization。澄清、记忆刷写和标题生成仍留在 Lead。

### 组装方式

1. `tool_error_handling_middleware.py` 中 `_build_runtime_middlewares` / `build_lead_runtime_middlewares` 构建 runtime 段
2. `backend/packages/harness/deerflow/agents/lead_agent/agent.py` 的 `build_middlewares` 追加 lead-only 与条件项
3. `load_configured_extension_middlewares` 加载配置启用的扩展中间件

### 自定义约束

- 行为可配置的 middleware 应实现 `release_policy_parameters() -> dict`（duck-typed `ReleasePolicyProvider`），使用 JSON 可序列化值；长文本用 `canonical_hash`
- 注入消息须打 provenance（见 [03](./03-上下文管理.md)）
- 图内 `create_chat_model` 须 `attach_tracing=False`

### 能否自定义

**支持。** 途径包括：

1. 在 harness 中新增 `AgentMiddleware` 并接入 `build_middlewares`
2. 通过 Plugins / Extensions 在 `install(registry, config)` 中注册 middleware 与工具
3. YAML 配置开关条件性启用已有中间件（summarization、memory、vision、plan_mode 等）

DeerFlow **不使用**独立的 `hooks.json` 命令型 handler 注册表；扩展点是 Python middleware 与插件入口。

## Plugins / Extensions

第三方 Python 包可暴露 `install(registry, config)`，由启动期只读的顶层 `plugins:` 列表按确定性顺序加载。

要点（详见 `backend/packages/harness/deerflow/extensions/AGENTS.md`）：

| 主题 | 约定 |
|------|------|
| 入口点 | PEP 621 group `deerflow.extensions`，例如 `example = "deerflow_extension_example:install"` |
| 配置边界 | `plugins:` 属运营控制的代码执行边界，不写入可通过 Gateway 改写的 `extensions_config.json` |
| `required: true` | 加载失败则 Gateway 构造失败；托管安装默认 `required: false` |
| CLI | `deerflow` → `extensions/cli.py`：`install` / `upgrade` / `list` / `enable` / `disable` / `remove` |
| 事务 | `ExtensionManager` 管理 `uv` 依赖组、锁文件、配置记录与回滚 |
| 本地源 | 目录快照到 `backend/extensions/sources/<distribution>/`，非 editable 链接 |

扩展可向 registry 注册 middleware、工具、观测者等；消息写入仍须遵守 provenance 与 release policy 约定。

## Skills

- 目录与配置加载；按需激活注入上下文
- 管理工具：`skill_manage`、`review_skill_package`
- 内容经 security scanner
- Bootstrap 类技能用于引导场景

Skills 扩展的是提示与可选工具面，不替换 Lead 图结构。

---

## MCP

- 在应用配置中声明 MCP server
- 工具桥入 `get_available_tools` 统一列表
- 与内置工具同名时需去重，避免模型选择歧义
