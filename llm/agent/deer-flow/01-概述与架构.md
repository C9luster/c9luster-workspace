# 01 — 概述与架构

## 定位

DeerFlow（Deep Exploration and Efficient Research Flow）2.0 是面向通用 Agent 工作负载的 **super agent harness**。研究类 workflow 是其能力子集，而非唯一形态。

核心能力面：

| 能力 | 说明 |
|------|------|
| Lead Agent | 基于 LangChain `create_agent` 与 LangGraph 编译图的主循环 |
| Sandbox | 按 Thread 隔离的执行环境（本机 / Docker / 可扩展 Provider） |
| Skills / MCP / Subagents / Memory | 可配置能力面 |
| Middleware 链 | 生命周期拦截与旁路策略（见 [07-扩展机制](./07-扩展机制.md)） |
| Gateway | HTTP/SSE、Thread 与 Run、文件上传、扩展管理 API |

2.0 相对早期版本为 harness 层重写：能力下沉到 Thread/Run、middleware、tools 与配置，而不是固定研究流水线。

## 运行时分层

```text
客户端
  │
  ▼
Nginx（统一入口，常见开发端口 2026）
  ├─ Frontend（Next.js，常见 3000）
  ├─ Gateway（FastAPI，常见 8001）
  │     │
  │     ▼
  │  LangGraph / lead_agent 图
  │     │
  │     ▼
  │  Harness 包 deerflow
  │  middleware · tools · sandbox
  │  skills · MCP · subagents · memory
  │
  └─ Provisioner（可选，常见 8002；远程沙箱供给等）
```

| 组件 | 常见端口 | 职责 |
|------|----------|------|
| Nginx | 2026 | 路由聚合 |
| Gateway | 8001 | REST/SSE、线程、上传、extensions API |
| Frontend | 3000 | Web UI |
| Provisioner | 8002 | 可选远程沙箱供给 |

## Harness 包布局

包根目录：`backend/packages/harness/deerflow/`。

| 目录 | 职责 |
|------|------|
| `agents/` | Lead Agent 工厂、ThreadState、middleware |
| `tools/` | 内置工具与工具装配 |
| `sandbox/` | Sandbox Provider 与线程绑定 |
| `skills/` | Skill 加载、激活、安全扫描 |
| `mcp/` | MCP 客户端与工具桥接 |
| `subagents/` | 子 Agent 执行器与批处理 |
| `memory/` | 长期记忆抽取与召回 |
| `config/` | YAML 配置模型 |
| `runtime/` | Checkpointer、StreamBridge、Run 生命周期 |
| `authz/` | 工具授权过滤 |
| `models/` | Chat model 工厂 |
| `tracing/` | Langfuse / LangSmith 回调 |
| `extensions/` | 插件加载与 ExtensionManager |

Gateway 位于 `backend/app/`，依赖已安装的 `deerflow` 包组装图；业务编排逻辑以 harness 为准，HTTP 层负责协议与资源管理。

## Lead Agent 组装

入口：`backend/packages/harness/deerflow/agents/lead_agent/agent.py`。

主要步骤：

1. 解析 `AppConfig` 与 per-agent YAML（`agents_config`）
2. `create_chat_model(...)`（图内调用需 `attach_tracing=False`，避免重复 span）
3. `build_middlewares(...)`：runtime 中间件、lead-only 中间件、配置的 extension middleware
4. 装配工具：内置 + skills + MCP + task continuity，并应用授权过滤
5. `create_agent(...)` 编译为 LangGraph
6. 在图调用根挂载 tracing callbacks

产出类型 `LeadAgentAssembly`：编译图与组装描述符（供扩展与观测使用）。

## 配置与约定

- 应用配置以 YAML 为主（模型、sandbox、skills、MCP、guardrails、plugins 等）
- Agent 名称经 `validate_agent_name` 校验
- 贡献与实现约定见仓库 `AGENTS.md`、`backend/AGENTS.md`（含 middleware 自描述、provenance 戳记等）
