# 08 — 会话持久化与恢复

DeerFlow 的可恢复单位是 **Thread**。图执行状态由 LangGraph Checkpointer 按 `thread_id` 持久化；工作区、上传文件与沙箱句柄由对应 middleware 绑定到同一 Thread。

## Checkpoint 保存什么

Checkpoint 是某一时刻 Thread 图状态的快照，供同一线程续跑、崩溃后恢复，以及澄清等待后继续。它承载的是可恢复的运行时局面，通常包括：

| 内容 | 作用 |
|------|------|
| channel 值 | ThreadState 各通道的当前值，如 `messages`、待办、目标、沙箱元数据 |
| channel 版本 | 判断哪些节点需要再次调度 |
| pending writes | 同一步未完成时已成功节点的中间写，恢复时避免整步重跑 |
| metadata | 步号、来源、channel 模式标记等 |

Lead 图在编译时挂上 checkpointer。Subagent 图以 `checkpointer=False` 编译：子任务是一次性执行，不继承父 Run 的检查点链，也不从检查点恢复。

## 后端

Checkpointer 与长期 Store 使用同一类后端。配置以应用配置中的 `checkpointer` 段为准；未配置时回落到 `database` 段。

| 类型 | 行为 |
|------|------|
| `memory` | 进程内 `InMemorySaver`；进程退出后丢失 |
| `sqlite` | 文件持久化（`SqliteSaver`）；缺省连接落到本地库文件 |
| `postgres` | `PostgresSaver`；需要 DSN，可指定 schema |

运行时同时提供同步工厂与异步工厂。同步路径供图编译与嵌入式调用复用单例；异步路径供 Gateway 上的 Run 使用。模式语义在编译后图的 channel 表中，三种后端都同时服务 `full` 与 `delta`。

## 读写入口

线程状态的读、写与历史查询经过 `CheckpointStateAccessor`。它绑定编译图、checkpointer 与已冻结的 channel 模式，在访问前写入模式标记并做兼容性检查，再返回物化后的状态。

直接读取 saver 中的原始 channel 值会绕过这层。在 `delta` 模式下，`messages` 通道存的是哨兵与逐步写入，原始读取看不到完整消息列表。仅需元数据时使用 `get_metadata` / `aget_metadata`，仍经过同一模式门控。

整段替换状态（回滚、上下文压缩、delta 续跑改写）走单独的 state-only 图：一个立即结束的空节点，只写入检查点，不调度 Agent 节点。reducer 通道（包括 `messages`）用 `Overwrite` 覆盖，避免 `add_messages` 把新旧列表合并。写入使用该线程实际编译时的 state schema，以保留 middleware 贡献的通道。

## Channel 模式：`full` 与 `delta`

模式由 `database.checkpoint_channel_mode` 选择，默认 `full`。Lead 组装与嵌入式客户端在编译图之前冻结该模式；同一进程内再改成另一种模式会抛 `CheckpointModeReconfigurationError`，需要改配置并重启。

| 模式 | 存储形态 |
|------|----------|
| `full` | 每个检查点写入完整 channel 值 |
| `delta` | `messages` 使用 LangGraph `DeltaChannel`：哨兵加上逐步 writes。存储与序列化随轮次线性增长，避免每步都重复保存整段消息列表 |

`database.checkpoint_delta.snapshot_frequency`（默认 10）决定 delta 通道隔多少步落一次完整快照。该节拍与模式一起冻结，写在编译图的 channel 表里，不写入 checkpoint metadata。

每个 delta 检查点在 metadata 中带 `deerflow_checkpoint_channel_mode: "delta"`。没有该标记的检查点按 `full` 处理，因此启用该功能之前的旧数据无需改写。

兼容方向不对称：

- `full` 进程打开 delta 线程时拒绝访问（`CheckpointModeMismatchError`）。直接用 full 语义读取 delta blob 会得到空的或部分的 `messages`。
- `delta` 进程可以读取遗留的 `full` 检查点，并用其内容为 delta 通道播种。支持的迁移方向是 **full → delta**。反向切换需要先物化并转换数据。

## 分支、再生成与回滚

`full` 检查点自带完整 channel 值，可以从历史检查点分叉，分支语义与 LangGraph 一致。

`delta` 不能从旧检查点分叉。祖先上的 pending writes 会包含已放弃的兄弟分支写入；这些写入重放后，新 Run 会带上本应被替换的回复。因此再生成或指定检查点续跑时，DeerFlow 先把目标检查点的完整状态写到当前 head（reducer 通道使用 `Overwrite`），去掉 `checkpoint_id` 选择器，再沿单一世系继续。被放弃的那一轮留在改写后 head 的祖先里。

回滚在 Run 开始前捕获不可变的 `RollbackPoint`（物化后的完整状态，以及当时的 pending writes）。捕获失败则关闭本次回滚。取消并回滚时：

- `full`：从运行前检查点分叉，并接回捕获到的 pending writes
- `delta`：在当前 head 上覆盖为捕获到的通道值，避免对已有兄弟写入的检查点再做分叉

## 其它随 Thread 恢复的资源

| 资源 | 维护方 | 与 Checkpoint 的关系 |
|------|--------|----------------------|
| 线程目录 | ThreadDataMiddleware | 工作区路径；文件本体在目录中 |
| 上传文件 | UploadsMiddleware | 进入线程可见清单；`list_uploaded_files` 供模型枚举 |
| Sandbox | SandboxMiddleware | Run 开始时获取、结束时释放；句柄不替代图状态 |
| 流事件 | StreamBridge | 把图执行事件推到 SSE。客户端用它观察进行中的 Run；续跑仍以 checkpoint 中的图状态为准 |
| DurableContext | Lead middleware | 跨轮委托与摘要等字段写入 Thread 状态，随检查点保存 |
| 已查看图像 | 共享 blob | 启用 blob 存储时，`view_image` 把图像字节存成引用。检查点不保存 base64；沙箱替换后按引用恢复 |

澄清等待期间图状态留在检查点中，用户回复后继续同一 Thread。进程重启后，sqlite 与 postgres 后端可恢复该 Thread 的图状态；memory 后端只在进程内存中，重启后丢失。产物文件通过 `present_file` 呈现，落在线程工作区，按目录策略保留或清理。
