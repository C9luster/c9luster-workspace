# 03 — 上下文管理

## ThreadState

Lead Agent 使用自定义 Thread 状态 schema（`backend/packages/harness/deerflow/agents/thread_state.py`）：

| 通道类别 | 内容 |
|----------|------|
| messages | 对话与工具轨迹 |
| 线程工作区元数据 | 目录、uploads、sandbox 句柄等（由 ThreadData / Uploads / Sandbox middleware 维护） |
| 任务连续性 / DurableContext | 跨轮委托、摘要、技能激活等可持久字段 |
| middleware 扩展槽 | 各中间件通过规范化 schema 声明写入通道 |

**消息 provenance 由服务端持有。** 注入或改写消息时，应通过 `deerflow_extension_api.provenance.provenance_kwargs()` 写入 `deerflow_content_kind`、`deerflow_producer_kind` 等字段，供下游区分模型输出、系统注入、摘要与记忆等内容来源。

## 上下文压缩（Summarization）

`DeerFlowSummarizationMiddleware`（工厂：`create_summarization_middleware`）：

- 在 token / 消息预算触及阈值时触发
- Compaction 保留状态中的 `SystemMessage`；瞬态指令使用 request wrapper
- Todo 提醒与 summarization 契约见上游 `docs/summarization.md`
- 行为参数通过 `release_policy_parameters()` 自描述，保证组装身份可哈希

实现侧重分区救援、锚定与最后消息回退，降低工具成对消息被裁切后不一致的风险。

## Memory

| 方向 | 机制 |
|------|------|
| 写入 | `MemoryMiddleware` 在适当时机排队抽取 |
| 召回 | DynamicContext 注入 `dynamic_context_memory`（带 provenance） |
| 开关 | `memory_config.should_use_memory_tools` 等配置项 |

记忆挂载在同一 Lead 循环上，由 middleware 与相关 tools 协同完成，而非独立 Agent 进程。

## Skills 进入上下文

1. 由配置与目录加载 Skill 清单
2. SkillActivation / DynamicContext 按需注入技能说明
3. `skill_manage` 等工具可增删技能；内容经 security scanner
4. Bootstrap 技能名集合（如 `bootstrap`）用于引导场景

Skills 改变模型可见的操作说明与可选工具面，不替换图拓扑。

## 其他上下文相关 middleware

| Middleware | 作用 |
|------------|------|
| ViewImageMiddleware | 多模态看图注入。图像字节可写入共享 blob，请求时再取出；base64 只出现在当次模型请求中，不进入检查点 |
| TitleMiddleware | 会话标题（独立模型调用；须遵守 tracing 标志约定） |
| TodoMiddleware | 待办与压缩提醒 |
| TerminalResponseMiddleware | 终态回复规范化 |
| ModelLength / Safety finish_reason | 将长度或安全结束原因转为可恢复行为 |
| SystemMessageCoalescing | 合并系统消息，减少碎片（常见于扩展侧） |

## 实现约束

- 注入逻辑须写入 provenance，否则观测与审计无法还原生产者
- 删除或改写 `tool_calls` 应使用 `clone_ai_message_with_tool_calls`，避免适配器重发陈旧 content blocks
- 子 Agent 回报视为不可信证据，写入 DurableContext 前须再校验
